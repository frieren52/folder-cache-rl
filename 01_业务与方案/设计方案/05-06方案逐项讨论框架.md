# 05—06 方案逐项讨论框架

> 持续更新。本文只记录当前仍有效的确定内容和必须通过首轮数据或轨迹选择的训练配置。
>
> **约束优先级：** 目录粒度、3% 容量和固定 LRU 遵守[业务约束](../业务约束.md)；时间回放与有限资源环境以本文和 05、06 模块方案为准。10通道 × 200 MiB/s保留为真实约束参考；目录是文件级动作的聚合代理，因此首版以30通道验证强化学习方法，决策周期为10秒。

## 0. 固定主流程

```text
历史访问
→ Actor生成静态查询、历史查询和融合权重
→ 双路ANN召回与融合
→ 环境先执行不依赖04当前预测的廉价Mask
→ 仅刷新剩余候选的历史向量和需求时间分布
→ 估计排队与完成时刻并执行动态Mask
→ Critic选择候选或STOP
→ 批量提交到有限通道FIFO
→ 回放需求、等待、完成、缓存与LRU
```

- 05使用多提前量需求监督训练Actor，06在同一个Actor上继续强化学习微调。
- 05和06共用状态构造器、Actor输入字段、向量归一化和历史索引更新规则。
- Actor不读取资源状态，不设STOP头；STOP由Critic与文件夹候选一起评价。
- 05回答“未来可能需要什么”，06回答“在当前队列下是否值得现在读取”。

## 1. 有限资源环境

### 1.1 基本配置

| 项目 | 正式规则 |
| --- | --- |
| 动作对象 | 02确定的49,922个目录聚合对象 |
| 缓存容量 | 数据总量的3%，按字节执行 |
| 淘汰算法 | 固定LRU |
| 决策周期 | 10秒，包含状态构造与模型推理 |
| 方法验证主并发 | 30通道 |
| 真实约束参考 | 10通道 |
| 上限诊断 | 60通道，仅在30通道可训练性检查失败时使用 |
| 单通道带宽 | 200 MiB/s |
| 固定准备时间 | 0 |
| 排队 | 中央FIFO，需求与预取共享 |
| 每步预取上限 | 环境超参数，首轮默认2个 |

单个对象无排队服务时间为：

```text
服务时间 = 对象大小字节数 ÷ 209,715,200
```

10通道和200 MiB/s是本任务的真实参考参数。目录聚合大小放大了单次动作成本，因此30通道用于方法验证；02已有10/30/60通道无预取结果，可分别作为黄金对照。不同通道场景必须使用独立Replay和Critic。

### 1.2 队列与批量预取

需求Miss触发需求取回，Actor/Critic动作触发预取。两类任务进入同一个中央FIFO并竞争当前环境版本配置的通道；一个任务占用一个通道，完成前持续占用。

同一对象已有排队中或服务中的任务时，后续需求合并到原任务，不重复取回，也不记为缓存Hit。新请求仍按真实完成时刻累计剩余等待。

Actor和双路ANN每10秒运行一次。Critic在影子队列与影子缓存中逐个选择候选，同步更新后续候选的预计排队、完成时刻、Mask和完成时LRU淘汰后果，直到选择STOP或达到当轮数量上限。当前批次按选择顺序一次提交到真实FIFO。

任务可以跨越任意多个10秒宏步。预计一小时内无法完成的候选直接Mask。无限并行和不共享带宽不得用于正式训练或主评价。

### 1.3 缓存与LRU

- **需求Hit：** 需求到达时对象已经完成并驻留缓存才记为Hit，同时移动到MRU。
- **在途合并：** 命中排队中或服务中任务仍需等待，不更新LRU。
- **完成入缓存：** 任务实际完成时才占用缓存并插入MRU，空间不足时连续淘汰LRU尾部。
- **同秒顺序：** 同秒完成任务按启动序号依次入缓存，全部完成后处理该秒需求。
- **批次顺序：** 同批预取按Critic选择顺序登记启动序号并进入FIFO。
- **容量约束：** 单个对象大小超过缓存总容量时直接Mask；每步数量上限由环境超参数控制，首轮默认2个，策略可提前STOP。
- **有效预取：** 预取对象完成后、被淘汰前至少发生一次真实访问才记为已使用。

### 1.4 事件顺序

决策时刻 `t` 按以下顺序执行：

```text
推进 ready_time <= t 的通道完成事件并更新缓存、LRU和通道
→ 消费 access_time < t 的历史并刷新dirty、Actor上下文和分层到期对象
→ 发布持久索引revision并构造Actor状态
→ Actor与双路检索生成自然候选
→ 记录持久召回得分并执行廉价Mask
→ 仅临时刷新剩余候选，不回写持久索引
→ 计算当前得分、排队与完成特征并执行动态Mask
→ Critic生成本轮批量
→ 计入Docker实测决策延迟并重新校验动作
→ 提交仍合法的动作并处理到 t+10s 的需求、通道启动与完成事件
```

同一秒的完成先于需求。状态不得读取 `access_time >= t` 的事件。

### 1.5 Actor与环境边界

Actor召回前不读取缓存、LRU、空闲通道、队列、在途任务或对象大小。候选生成后，环境和Critic才能读取这些执行信息。

通道数和带宽不得写入Actor输入。资源状态只由环境与Critic读取，不改变Actor需求语义。

### 1.6 预热与记录

2026年6月17日尾部和6月18日用于预热，不生成正式05监督样本。预热连续回放04历史状态、缓存、LRU、通道、FIFO和在途任务；第一日结束保存相同 `snapshot_time` 的历史索引与环境起点。

环境至少记录任务来源、提交时刻、排队开始、服务开始、完成时刻、合并请求、首次需求、淘汰、是否使用、受害对象和通道占用，供06计算奖励和诊断。这些记录不进入Actor输入。

## 2. 模型输入

### 2.1 Actor输入

每次输入最多256个不同对象：

```text
最近访问128个 + 一小时热门排序补齐至256个
```

最近集合优先；热门对象与最近集合重合时不重复放入，但两个来源标记都为1，并继续扫描热门排序直至补满或列表耗尽。

每个对象为259维：

```text
静态向量（static_vector）[128]
历史向量（history_vector）[128]
历史有效标记[1]
最近访问来源标记[1]
一小时热门来源标记[1]
```

历史缺失时向量填0、历史有效标记为0。上下文不足时使用全0 PAD，编号为 `-1`，并通过上下文有效性掩码屏蔽。

Actor不使用位置编码。上海日内正弦值与余弦值在集合汇总后拼接，首版不增加星期、月份、资源或缓存特征。

### 2.2 历史索引与需求时间分布

- 04模型冻结，所有输入只使用 `access_time < t` 的历史。
- 第一日结束建立24小时活跃对象初始索引；此后dirty和Actor上下文立即刷新，近1小时活跃对象最多5分钟刷新一次，1～24小时活跃对象最多1小时刷新一次，跨过1小时边界时立即刷新，超过24小时未访问则删除。
- 分层对象用确定性的 `next_refresh_time` 调度；初始化时按 `path_index` 稳定散列到对应层的10秒时间槽。所有来源合并去重后批量调用04，只有持久刷新或删除可以增加 `history_revision`。
- ANN候选使用本轮持久索引revision；合并最多512个候选后，06先Mask已缓存、排队/在途、超大、无效、按FIFO与通道完成下界可确定一小时内无法完成、晚于计分终点和末尾结算区对象，再仅对剩余候选按当前 `t` 临时刷新历史向量和04需求时间分布。
- 04正式输出10档首次访问时间分布：9个一小时内时间档和“未来一小时无访问”档；9个访问档边界固定为`[0, 5, 10, 30, 60, 120, 300, 600, 1800, 3600]`秒，无访问档索引为9。
- 候选当前刷新结果只供重排和Critic使用，不写入持久索引。轨迹分别记录 `retrieval_history_score`、`retrieval_fusion_score`、`current_history_score`、`current_fusion_score`、`history_revision` 和 `candidate_as_of_time`；廉价Mask对象的当前分数和时间为空。

### 2.3 Critic输入

Critic复用Actor的因果对象集合与状态编码结构，通过独立编码器得到256维需求状态，并加入空闲/服务通道、FIFO任务与字节、缓存占用、在途任务和当前影子批次等10维资源状态。

候选特征至少包括：

```text
静态向量与历史向量                                      256
历史向量有效标记                                          1
静态、当前历史和当前融合得分                              3
对象大小占缓存容量比例                                    1
淘汰对象数和淘汰字节比例                                  2
被淘汰对象近1小时访问和与最小距今时间                     2
与已选批次最大相似度                                      1
是否淘汰与是否已选                                        2
预计排队秒、服务秒和完成距今秒                            3
完成前访问概率与完成后访问概率                            2
预计完成超出1小时预测范围标记                              1
未来5分钟预计访问次数                                      1
```

预计完成时刻根据当前影子FIFO、通道可用时刻、同批已选对象和对象服务时间计算。完成前后访问概率由预计完成时刻在04的10档时间分布上积分得到。预计完成超过1小时时，完成前访问概率取未来1小时访问概率、完成后访问概率填0，并置超出范围标记；不得把04的“未来1小时无访问”档解释为永不访问。

计数、字节和时间使用 `log1p`；固定范围比例保持原范围；缺失或不适用数值填0并保留相应标记。

## 3. 模型设计

### 3.1 Actor

```text
256 × 对象输入[259]
→ 全连接层(259,256) + GELU + 层归一化
→ 无位置编码Transformer编码器
→ 可学习查询汇总
→ 拼接日内正弦值/余弦值
→ 全连接层(258,256)
→ 整体状态[256]
   ├─ 128维静态查询 + L2归一化
   ├─ 128维历史查询 + L2归一化
   └─ 静态/历史融合权重 + Softmax
```

状态维度256、4个注意力头、前馈层维度512、丢弃率0.1。首版Transformer固定4层，2层和6层仅作后续候选，本轮不比较。集合汇总支持配置固定的 `dot_product` 和4头 `mha` 两条路由，默认前者；训练中不动态切换。两条路由的4层Actor参数量分别为2,308,354和2,571,522。

Actor不输出对象ID、候选数量、预计完成时间或STOP。

### 3.2 Critic

Critic包含独立需求状态编码器、资源状态融合、候选编码器、已选批次汇总、候选价值头和STOP价值头。

进入06时，Critic需求状态编码器从05 Actor状态编码器复制；Actor查询头和融合权重头不复制。初始化后Actor与Critic参数独立更新，避免TD梯度直接破坏05需求表示。

首版候选输入固定为275维，Critic沿用Actor的汇总路由。`dot_product` 下在线Critic为2,763,650、与Target合计5,527,300；`mha` 下在线Critic为3,026,818、与Target合计6,053,636。首版不增加Actor Target。特征顺序、网络层和参数统计见[06详细设计](06_强化学习/详细设计.md)。

## 4. 训练任务

### 4.1 05监督训练

05每10秒生成一条状态样本并训练Actor，与06的10秒决策周期直接对齐。未来1小时正对象按首次需求距 `t` 落入四个互斥层：

| 提前量层 | 时间范围 |
| --- | --- |
| 即时需求 | `[t,t+5s)` |
| 短期需求 | `[t+5s,t+30s)` |
| 中期需求 | `[t+30s,t+5min)` |
| 提前需求 | `[t+5min,t+1h)` |

05不按当前队列裁剪正样本，否则Actor会绑定某个资源快照；能否按时完成由06决定。

每个截点最多使用96个训练正样本。超过时首版四层各分配24个目标名额，空余名额按其他层剩余规模重分配；每层先保留访问次数最高的最多8个对象，再固定种子随机选择并记录采样权重。完整一小时正样本集合始终保留用于自然评价和排除伪负样本。

每个正样本最多配3个负样本。总体负样本按5分钟内45%、5分钟至1小时27%、1至24小时18%、24小时未活跃全局对象10%采样，并排除未来一小时完整正样本集合。模型召回困难负样本作为后续候选；若启用，只能从训练段首轮Actor的高分误召回中构造并发布新数据版本，首版不执行。

Actor输出得分为：

```text
静态得分 = 静态查询 · 对象静态向量
历史得分 = 历史查询 · 对象历史向量
融合得分 = 静态权重 × 静态得分 + 历史权重 × 历史得分
```

三路均使用：

```text
单对损失 = softplus(负样本得分 - 正样本得分)
```

历史排序只使用正负两端历史都有效的样本对；正负两端读取截点已发布的持久索引向量，用来拟合第一阶段历史Top-256召回。融合排序对已采样正负对象按当前 `t` 临时调用04，两端只读取 `access_time < t` 的历史，用来拟合运行时候选重排；临时向量不写入索引。历史缺失仍参加静态和融合排序，历史得分按0处理。损失先在四个提前量层内按采样权重归一化，再对有效层等权平均，最后对batch中的有效截点等权平均。

05不设置验证集：6月19—23日训练，固定完成20轮并发布第20轮模型；训练过程中不得读取6月24日测试集，也不使用早停。训练完成后只对正式模型运行一次测试，报告5秒、10秒、30秒、5分钟和1小时自然Recall；测试结果不得用于选择轮次、检查点或反向调参。

### 4.2 06奖励与动作

策略环境和无预取基线环境使用相同请求流、3%容量、当前场景通道数、200 MiB/s、无额外固定准备时间、FIFO、LRU和预热起点，此后独立维护缓存、通道、队列和在途任务。方法训练默认使用30通道；10通道参考与60通道诊断分别生成独立环境版本。

对宏步内每条逻辑请求，分别计算策略与基线的命中请求数差和命中字节差。使用训练段每宏步平均请求数、平均请求字节作为固定尺度，首版奖励为：

```text
奖励 = 0.8 ×（策略命中字节 - 基线命中字节）÷ 字节尺度
     + 0.2 ×（策略命中请求数 - 基线命中请求数）÷ 次数尺度
```

预取按时命中产生正收益；污染导致策略Miss而基线Hit时产生负收益。等待、额外读取、未使用预取、通道竞争和污染明细单独进入副作用账本与检查点过滤，不替代字节命中优先、读取次数命中共同评价的业务目标。

一个宏步只运行一次Actor和双路ANN。候选微步选择对象时只更新影子批次、队列和缓存，真实时间不推进、即时奖励为0、折扣为1；选择STOP时计入决策延迟、重新校验并提交批次，再推进真实环境到10秒周期末尾。

Critic使用在线网络选动作、Target Critic估值、Double-Q和Huber Loss。宏步双命中差分奖励只放在最终STOP transition；10秒STOP使用一小时半衰期的连续时间折扣，候选选择微步折扣为1。

### 4.3 Replay与Actor强化更新

Replay以完整10秒宏步为存储与采样单位。每次均匀抽宏步，从中均匀抽一个非STOP微步，并始终加入同宏步最终STOP；直接STOP宏步只加入STOP。

宏记录至少绑定Actor输入引用、行为查询、候选ID、`retrieval_history_score`、`retrieval_fusion_score`、`current_history_score`、`current_fusion_score`、`candidate_as_of_time`、Mask及原因、03/04/ANN版本、历史索引revision、初始缓存/LRU/通道/FIFO/在途可重放状态、选择顺序、奖励账本、下一宏步、环境版本和SHA256。

Actor强化更新采用交替训练：

```text
固定Actor生成自然候选和环境轨迹
→ 训练并校准Critic
→ 以候选价值减STOP价值构造优势排序监督
→ 加入原05多提前量监督损失作为锚定
→ 更新同一个Actor
→ 废弃旧候选轨迹并重新回放
```

ANN候选ID不可导，不能把TD Loss直接穿过候选ID反传给Actor。06首版不需要Actor Target。

## 5. 数据与评价

### 5.1 05数据

状态必须由连续时间回放生成，不能随机打散日志后重建。训练集和测试集之间历史索引不重置；每个切分末尾1小时不生成新监督标签，只保持状态推进和结算。

```text
data/vector_store/initial_history_index.npz
data/actor_samples_manifest.json
```

`actor_samples.parquet` 核心字段为：

```text
sample_id, cutoff_time, split

最近访问来源标记[256], 一小时热门来源标记[256]
```

### 5.2 05自然召回

自然评价从第一日初始历史索引顺序重放，复用dirty、上下文、近期层、长期层和跨层刷新；召回后对最多512个并集候选全部临时刷新但不回写索引，不注入未来正样本，也不应用缓存、在途、容量或队列Mask。

静态和历史Exact检索各取Top-256，合并最多512个，再分别按持久融合得分和当前融合得分取Top-256。对5秒、10秒、30秒、5分钟和1小时累计正样本报告静态、历史、持久融合、当前融合和并集的微平均/宏平均Recall，并附加四个互斥首次需求层结果；5秒只作紧急需求诊断，5分钟和1小时为主要召回指标。并集只作为候选池覆盖上限，不与Top-256结果作同规模比较。

`sampled_*` 只用于训练诊断。近似ANN必须相对Exact单独报告Recall损失和延迟。

### 5.3 06轨迹

06按自然时间生成完整宏步轨迹，不能从05样本行独立随机启动环境。训练Replay只在轨迹生成后按宏步均匀抽样。

30通道、200 MiB/s为方法验证主轨迹和检查点选择环境。每宏步最大预取数配置为2，策略可选择0、1或2个；10通道保留为真实资源参考。

现有02有限带宽报告中的10/30/60通道场景分别用作无预取黄金对照。训练前先检查30通道的合法动作覆盖率；不足时才使用60通道验证带宽上限下是否存在方法信号。预计一小时内无法完成或晚于计分终点的候选直接Mask，不进入合法动作集合。
