# 03 静态语义编码模型详细设计（初稿）

本设计说明如何训练并交付静态语义编码模型。全量目录向量生成和向量库构建在后续阶段完成。

## 1. 模型输入与输出

### 1.1 输入

输入文件位于：

- `02_全局数据/artifacts/path_sematic/semantic_catalog.csv`：业务语义组。
- `02_全局数据/artifacts/path_sematic/embedding_records.csv`：逐目录语义和实例信息。

以 `path_index=0` 为例，送入模型的内容为：

```json
{
  "semantic_text": "数据域 FY3；卫星或航天平台 FY3H；载荷或仪器 MERSI；数据等级 L2L3；产品 OCA；区域或轨道类型 ORBIT；空间分辨率 10KM",
  "instance_text": "存储根目录 FYDATAOUTSHARE；子系统 DATAIOT；路径类型 outshare_dataiot_fy3；观测日期 2026年3月31日",
  "date_ordinal": 20543,
  "has_observe_date": 1,
  "raw_path": "/FYDATAOUTSHARE/DATAIOT/FY3/FY3H/MERSI/L2L3/OCA/ORBIT/010KM/2026/20260331"
}
```

- **业务语义输入：** `semantic_text` 直接取 `embedding_text`。
- **目录实例输入：** `instance_text` 按顺序拼接 `source_text` 和 `instance_context`。
- **数值日期输入：** `date_ordinal` 按训练集统计量归一化；日期缺失时置零并令 `has_observe_date=0`。
- **训练辅助输入：** `raw_path` 只用于实例对齐训练。
- **文本预处理：** 分词、补齐和 attention mask 由 BGE 分词器自动生成。

`path_index` 由接口原样携带，用于对应输出向量，不进入模型计算。

### 1.2 输出

模型输出形状为 `[B, D_static]` 的 `float32` 向量矩阵，初稿取 `D_static = 128`。封装接口返回：

| 字段 | 类型 | 形状 |
| --- | --- | --- |
| `path_indices` | `int64` 数组 | `[B]` |
| `vectors` | `float32` 数组 | `[B, D_static]` |

批量大小为 1 时的格式示例：

```json
{
  "path_indices": [0],
  "vectors": {
    "dtype": "float32",
    "shape": [1, 128],
    "first_row_preview": [0.0312, -0.0845, 0.0177, 0.0197]
  }
}
```

示例数值仅表示接口格式。正式输出必须保持输入顺序、全部为有限值，并逐行完成 L2 归一化。

## 2. 模型结构

初稿采用冻结的 BGE-M3 编码两段文本，并为实例分支增加数值日期输入。以下维度和层参数作为首版实现值，统一写入 `model_config.json`：

```text
业务语义文本 → BGE-M3 → 语义投影头 → 64 维语义向量

目录实例文本 → BGE-M3 → 1024 维文本表示 ─┐
                                          ├→ 拼接 → 实例投影头 → 64 维实例向量
日期序数 + 有效标记 → 日期投影层 → 16 维 ─┘

64 维语义向量 + 64 维实例向量 → 融合层 → 128 维静态向量 → L2 归一化
```

### 2.1 BGE-M3

- 使用 `BAAI/bge-m3`，参数全程冻结。
- 配置必须指定模型 revision；首次准备数据时将解析到的 commit hash 和分词器配置写入 `model_config.json` 与 `manifest.json`，训练、评估和推理必须使用同一版本。
- 生产 Docker 环境使用 NVIDIA GPU；BGE-M3 以 FP16 加载，编码批量为 8，缓存向量以 `float16` 保存。
- 最大文本长度为 256，使用 `last_hidden_state[:, 0, :]` 作为 1024 维文本向量。
- 业务语义文本、目录实例文本和训练用原始路径共用同一个 BGE-M3。

### 2.2 语义投影头

```text
1024
→ LayerNorm(1024, eps=1e-5)
→ Linear(1024, 256, bias=True)
→ GELU
→ Dropout(0.1)
→ Linear(256, 64, bias=True)
→ L2 Normalize
```

输出 64 维业务语义向量。

### 2.3 日期投影层

日期数值先按以下方式处理：

```text
有日期：date_value = (date_ordinal - 训练集均值) / 训练集标准差
无日期：date_value = 0，has_observe_date = 0
[date_value, has_observe_date] → Linear(2, 16) → GELU → 16 维日期向量
```

`Linear(2, 16)` 使用偏置。训练集均值和标准差写入 `model_config.json`，推理时固定使用。

### 2.4 实例投影头

1024 维实例文本向量与 16 维日期向量拼接为 1040 维输入：

```text
1040
→ LayerNorm(1040, eps=1e-5)
→ Linear(1040, 256, bias=True)
→ GELU
→ Dropout(0.1)
→ Linear(256, 64, bias=True)
→ L2 Normalize
```

输出 64 维目录实例向量。原始路径视图训练时复用同一个实例投影头，并使用同一目录的日期特征。

### 2.5 融合层

```text
64 维语义向量 + 64 维实例向量
→ Concatenate(128)
→ LayerNorm(128, eps=1e-5)
→ Linear(128, 128, bias=True)
→ L2 Normalize
```

输出最终 128 维静态向量。融合层通过训练学习两路信息的使用方式，不设置固定融合权重。

### 2.6 训练辅助头

辅助头只提供训练监督，`encode` 推理接口不返回其结果：

- 64 维语义向量分别连接 `Linear(64, C_product)`、`Linear(64, C_instrument)` 和 `Linear(64, C_level)` 多标签分类头。
- 64 维实例向量连接日期回归头：`Linear(64, 1)`。
- 64 维实例向量分别连接 `Linear(64, C_archive_root)` 和 `Linear(64, C_subsystem)` 分类头。

各类别数量和标签表写入 `model_config.json`，辅助头参数与主模型一同保存。

原始路径只作为实例分支的训练视图；正式推理使用同一套输入构造规则生成业务语义文本和目录实例文本。

## 3. 训练目标

所有分支输出均已完成 L2 归一化，因此余弦相似度可直接按点积计算：

```text
sim(u, v) = u · v
```

### 3.1 业务语义任务

输入为锚点语义向量 `s_a`、正样本向量 `s_p` 和负样本向量 `s_n`：

```text
L_sem_rank = mean(max(0, 0.15 + sim(s_a, s_n) - sim(s_a, s_p)))
```

冻结 BGE-M3 对同一批文本生成归一化基准向量 `t_a`、`t_p` 和 `t_n`：

```text
L_distill = mean(0.5 × (
    (sim(s_a, s_p) - sim(t_a, t_p))²
  + (sim(s_a, s_n) - sim(t_a, t_n))²
))
```

产品、仪器和数据等级从 `semantic_sequence` 生成多热标签，使用多标签分类损失：

```text
L_attr = mean(
    BCEWithLogits(product_logits, product_labels)
  + BCEWithLogits(instrument_logits, instrument_labels)
  + BCEWithLogits(level_logits, level_labels)
)
```

字段缺失时跳过对应分类项。语义任务总损失为：

```text
L_sem = L_sem_rank + 0.25 × L_distill + 0.20 × L_attr
```

**目的：** 排序损失学习业务关系，蒸馏保持 BGE 原有相似结构，属性分类确保关键业务字段进入语义向量。

### 3.2 目录实例任务

锚点 `i_a` 来自目录实例文本，正样本 `i_p` 来自同一目录的原始路径，负样本 `i_n` 来自其他目录：

```text
L_inst_align = mean(max(0, 0.15 + sim(i_a, i_n) - sim(i_a, i_p)))
```

日期回归头从 `i_a` 预测归一化日期序数，仅对 `has_observe_date=1` 的样本计算：

```text
L_date = mean((predicted_date - normalized_date)²)
```

归档根和子系统标签从 `source_context` 提取，使用分类损失：

```text
L_source = 0.5 × (
    CrossEntropy(archive_root_logits, archive_root_label)
  + CrossEntropy(subsystem_logits, subsystem_label)
)
```

来源字段缺失时跳过对应分类项。实例任务总损失为：

```text
L_inst = L_inst_align + 0.20 × L_date + 0.10 × L_source
```

**目的：** 对齐结构化实例描述和原始路径，并明确要求实例向量保留日期、来源和子系统信息。

### 3.3 最终表示任务

输入为融合后的锚点静态向量 `z_a`、正目录向量 `z_p` 和负目录向量 `z_n`：

```text
L_final = mean(max(0, 0.15 + sim(z_a, z_n) - sim(z_a, z_p)))
```

**目的：** 直接约束最终交付模型的输出空间，使最终向量同时保留业务相似性和目录实例差异。

### 3.4 防坍塌损失

对语义、实例和最终表示分别计算批内各维标准差。设一批归一化向量为 `X`：

```text
V(X) = mean_j(max(0, 0.05 - sqrt(var(X[:, j]) + 1e-4)))

L_collapse = (V(X_sem) + V(X_inst) + V(X_final)) / 3
```

每个 `X` 均包含该任务批次中的锚点、正样本和负样本。该损失要求各维保持最低变化量，防止所有输入产生相同向量或只使用少数维度。

### 3.5 总损失

```text
L_total = 1.0 × L_sem + 0.5 × L_inst + 1.0 × L_final + 0.02 × L_collapse
```

三项任务损失先分别对有效样本求平均，再按上述权重相加。三元组 margin 均为 `0.15`。防坍塌目标标准差为 `0.05`，权重为 `0.02`；所有参数写入训练配置，并随模型一起保存。

## 4. 样本构造与切分

### 4.1 数据切分

对 `semantic_group_id` 的 UTF-8 字节计算 SHA-256，取摘要前 8 字节按大端无符号整数转换后对 10 取模：结果为 `0～7` 时进入训练集，结果为 `8～9` 时进入验证集。同一语义组的所有目录只能进入一个集合，不设置测试集。三元组的锚点、正样本和负样本必须来自同一集合。

### 4.2 语义排序样本

每条样本包含 1 个锚点语义组、1 个正语义组和 1 个负语义组：

- 正样本中 70% 要求产品、仪器和数据等级一致，30% 要求产品、仪器一致且数据等级无已知冲突。
- 负样本中 70% 为产品或仪器冲突的困难负样本，30% 为随机不同语义组。
- 未识别字段不作为正负关系证据。

指定类型没有候选时由另一类型补足；仍无法组成三元组则跳过该锚点。

同一条语义样本还携带三组冻结 BGE 基准向量，以及产品、仪器和数据等级多热标签，分别用于蒸馏和属性分类。

关系示例：

```text
锚点：FY3H / MERSI / L2L3 / OCA / ORBIT / 10KM
正样本：FY3F / MERSI / L2L3 / OCA / ORBIT / 10KM
负样本：FY3H / MERSI / L2L3 / CLM / ORBIT / 1000M
```

### 4.3 实例对齐样本

每条样本包含 1 个实例文本锚点、同一目录的原始路径正样本和 1 个其他目录负样本。负样本中 70% 取同语义组但日期或来源不同的目录，30% 取随机不同语义组。

锚点同时携带归一化日期序数、日期有效标记、归档根标签和子系统标签，用于日期回归和来源分类。

```text
锚点：path_index=0，观测日期 2026年3月31日
正样本：path_index=0 的原始路径
负样本：path_index=1，同语义组，观测日期 2026年3月12日
```

### 4.4 最终表示样本

最终表示样本复用语义排序三元组，并从三个语义组中各抽取 1 个具体目录：

```text
锚点目录：FY3H / MERSI / L2L3 / OCA / 20260331
正目录：FY3F / MERSI / L2L3 / OCA / 20260520
负目录：FY3H / MERSI / L2L3 / CLM / 20260210
```

`supported_clean` 和 `supported_with_unresolved` 参加全部任务；`fallback_raw` 只参加实例对齐和推理覆盖，不构造语义排序与最终表示样本。

### 4.5 任务采样比例

每次参数更新分别抽取等量的语义排序、实例对齐和最终表示样本，三种任务比例为 `1:1:1`。每条任务样本内部固定为 1 个锚点、1 个正样本和 1 个负样本；蒸馏、属性分类、日期回归、来源分类和防坍塌约束复用这些样本，不额外采样。

### 4.6 语义召回评估样本

语义召回不复用随机采样的训练三元组，而是在验证集上确定性地构造完整相关集合：

- 查询为验证集中的可靠语义组，候选为验证集中除查询自身外的全部可靠语义组。
- 查询与候选的产品、仪器和数据等级均有值且完全一致时，候选记为相关样本；其他字段未知不作为相关证据。
- 没有相关样本的查询不参与召回率平均，但必须报告有效查询数及其占验证集语义组总数的比例。
- 召回使用模型输出的 64 维语义向量，以余弦相似度排序；弱正样本只用于训练增强，不进入首版召回相关集合。

设查询 `q` 的全部相关样本为 `P(q)`，前 10 个召回结果为 `Top10(q)`：

```text
Recall@10(q) = |Top10(q) ∩ P(q)| / |P(q)|
Semantic Recall@10 = 所有有效查询的 Recall@10 平均值
```

## 5. 训练过程

```text
构造两层文本和数据切分
→ 归一化日期特征并离线生成冻结 BGE-M3 表示
→ 训练投影头、融合层和辅助任务头
→ 每轮在验证集评估
→ 选择最佳模型
```

初稿训练参数如下，均由配置文件管理：

| 参数 | 初稿值 |
| --- | ---: |
| 优化器 | AdamW |
| 学习率 | 0.001 |
| 权重衰减 | 0.0001 |
| 批量大小 | 每个任务 256 |
| 梯度裁剪 | 1.0 |
| 最大轮数 | 30 |
| 提前停止 | 连续 5 轮无改善 |
| 随机种子 | 2026 |

每轮计算验证集 `L_total`，按其最小值保存最佳模型；连续 5 轮未降低则提前停止。排序、召回、日期回归和来源分类结果只作为评估指标报告。交付模型保存主模型和辅助头参数，训练配置、标签表和输入数据版本写入模型配置。

### 6.2 文件职责

- `README.md`：运行方式和输入输出说明。
- `requirements.txt`：Python 依赖。
- `config/`：保存模型、采样和训练参数。
- `data/`：保存训练集、验证集、离线 BGE 表示及其元数据，均由 `prepare_data.py` 从 02 的两个输入文件生成。
- `scripts/`：提供模型下载、数据准备、训练和评估入口。
- `src/`：保存数据处理、采样、模型、损失、训练循环和推理实现。
- `outputs/`：保存正式交付的模型、模型配置、评估报告和文件清单。

### 6.3 模型加载

`model_config.json` 记录输入字段、文本拼接顺序、日期归一化参数、模型结构、标签表、向量维度、BGE commit hash 和分词器配置；`manifest.json` 记录数据版本、模型版本、BGE 版本和全部交付文件摘要。

```python
encoder = StaticSemanticEncoder.load("outputs")
result = encoder.encode(records)
```

`encode` 接收一批 02 解析后的目录记录，并返回 `path_indices` 和归一化静态向量。后续阶段使用该接口生成全量目录向量并构建向量库。

## 7. 验收

验收只看两项：

1. **能否跑通：** 在独立环境中加载交付模型，完成从 02 解析记录输入到静态向量输出的完整推理。
2. **验证集表现：** 报告语义 `Recall@10`、有效查询覆盖率和三类任务的正负关系排序结果，并达到评估配置中预先规定的门槛。
