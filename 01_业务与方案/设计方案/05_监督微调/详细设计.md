# 05 监督微调详细设计

本设计说明 05 如何加载 03/04 模型、构建静态与动态候选向量库、训练 Actor，并将向量库和监督 Actor 交付给 06。05 只学习未来目录需求，不读取缓存、LRU、对象大小、通道、队列或在途状态，也不选择最终预取批次和 STOP。

## 1. 模型输入与输出

### 1.1 输入产物

05 不接收上游预先生成的向量库，只接收数据和模型：

- **02 数据：** `path_catalog.csv` 确定对象身份与大小，`embedding_records.csv` 用于静态编码，`raw/access_*.txt` 用于历史回放。
- **03 模型：** 从配置指定的正式制品目录加载 `manifest.json`、`model_config.json` 和 `static_encoder.safetensors`；同时提供 manifest 绑定版本的 BGE 基座模型或本地缓存。
- **04 模型：** 从配置指定的正式 release 目录加载 `manifest.json`、`model_config.json`、`feature_stats.json` 和 `dynamic_encoder.safetensors`。训练目录中的 `best.pt`/`last.pt` 不能直接作为 05 输入。

制品路径不得硬编码。05 使用 03 模型生成全量静态向量，使用 04 模型和访问事件建立动态历史索引。加载时校验 `path_index` 覆盖、模型 manifest、SHA256、128 维输出和时间顺序；任一不一致都停止运行。

### 1.2 候选向量库构建

05 首先构建双路候选向量库：03 模型一次性编码全部目录，生成 `[N,128]` 静态向量及 `path_index` 映射；04 模型连续回放 6 月 18 日完整一天，在 `2026-06-19 00:00:00` 为过去 24 小时内活跃对象建立初始动态历史索引。

此后每个 10 秒决策截点 `t` 严格执行：

```text
消费 access_time < t 的新增事件
→ 确定 dirty、Actor 上下文、近期层到期、长期层到期和跨层对象
→ 合并去重并批量刷新历史向量
→ 发布新的 history_revision
→ 构造 Actor 输入并执行候选检索
→ 05 评价刷新全部候选；06 先做廉价 Mask 再刷新剩余候选
```

持久索引采用分层刷新：dirty 和 Actor 上下文在本轮立即刷新；`[t-1h,t)` 活跃对象最多 5 分钟刷新一次；`[t-24h,t-1h)` 活跃对象最多 1 小时刷新一次；对象从近期层跨入长期层时立即刷新；超过 24 小时未访问则删除。刷新必须先于 Actor 推理，`access_time=t` 的事件留到下一截点。

各对象用确定性的 `next_refresh_time` 调度，避免同一截点集中编码。初始化时令 `slot_count=30`（近期层）或 `360`（长期层），`refresh_slot=path_index mod slot_count`，并设 `next_refresh_time=snapshot_time+10s×(refresh_slot+1)`；后续每次持久刷新后分别设为 `t+300s` 或 `t+3600s`。所有来源先合并去重，一个对象每轮最多调用一次 04。只有该持久刷新流程可以增加 `history_revision`：本轮存在向量写入或过期删除时递增一次，否则沿用原 revision。

召回后的候选刷新只生成当前候选向量、04 预测和重排得分，不回写持久历史索引，也不改变本轮 `history_revision`。样本、检索和 06 轨迹必须同时记录持久召回版本及候选当前版本。静态向量、初始动态索引及输入制品摘要统一记录在 `vector_store_manifest.json`。

### 1.3 Actor 输入

每个决策截点形成一条整体状态。这里的 256 个对象是 Actor 上下文，不是后续静态、历史两路各 256 个检索候选；上下文按 4.2 的规则选择。批量输入为：

| 字段 | 类型 | 形状 |
| --- | --- | --- |
| `context_features` | `float32` | `[B,256,259]` |
| `context_valid_mask` | `bool` | `[B,256]` |
| `time_features` | `float32` | `[B,2]` |

每个上下文对象的 259 维表示为：

```text
静态向量                                      128
动态历史向量                                  128
历史有效标记                                    1
最近对象标记                                    1
一小时热门标记                                  1
合计                                          259
```

动态历史向量必须读取 1.2 在本轮刚发布的 `history_revision`。历史向量缺失时填 0，并令历史有效标记为 0。上下文不足 256 个对象时使用全 0 PAD，PAD 的 `path_index=-1`，历史有效标记和两个选择标记均为 0。

`context_valid_mask=True` 表示真实对象，`False` 表示 PAD；传入 Transformer 的 `src_key_padding_mask` 时必须逻辑取反。

`time_features` 使用上海本地时间的一天内周期：

```text
day_ratio = 当天已过去秒数 / 86400
time_sin = sin(2π × day_ratio)
time_cos = cos(2π × day_ratio)
```

时间特征在目录集合汇总后加入，不复制到每个对象。首版不加入星期、月份、节假日、缓存或资源特征。

### 1.4 Actor 输出

Actor 推理接口返回：

| 字段 | 类型 | 形状 |
| --- | --- | --- |
| `static_query` | `float32` | `[B,128]` |
| `history_query` | `float32` | `[B,128]` |
| `fusion_weights` | `float32` | `[B,2]` |

两路查询逐行使用 `eps=1e-12` 的安全 L2 归一化，避免零范数产生非有限值。`fusion_weights[:,0]` 固定为静态权重，`fusion_weights[:,1]` 固定为历史权重；两个权重均非负且逐行和为 1。所有输出必须为有限值。

Actor 不直接输出 `path_index`、候选数量、对象大小、预计完成时间或 STOP。候选对象由检索层根据两路查询生成，最终预取对象和停止位置由 06 的环境与 Critic 决定。

## 2. 模型结构

首版 Actor 使用固定 4 层、无位置编码的集合编码器：

```text
256 × 对象表示[259]
→ Linear(259,256) + GELU + LayerNorm
→ 无位置编码 TransformerEncoder
→ 可学习查询汇总
→ 拼接日内正弦值和余弦值
→ Linear(258,256)
→ 整体需求状态[256]
   ├── Linear(256,128) + L2 Normalize → 静态查询[128]
   ├── Linear(256,128) + L2 Normalize → 历史查询[128]
   └── Linear(256,2) + Softmax        → 两路融合权重[2]
```

### 2.1 对象投影

```text
对象表示[259] → Linear(259,256) → GELU → LayerNorm(256)
```

所有 Linear 层包含偏置。PAD 虽经过投影，仍必须由 `context_valid_mask` 屏蔽，不能参与注意力或汇总。

### 2.2 集合编码器

首版堆叠 4 个 `TransformerEncoderLayer`：隐藏维度 256、4 个注意力头、前馈层 512、GELU、Dropout 0.1、`batch_first=True`、`norm_first=False`、LayerNorm `eps=1e-5`，编码器末尾不再增加独立 LayerNorm。2 层和 6 层仅作后续候选，本轮不比较。

编码器不使用位置编码，因此对象集合一致重排后，输出应在数值容差内保持不变。

### 2.3 集合汇总与时间融合

集合编码器输出 `H∈R^[B,256,256]`，再通过固定的 `pooling_mode` 汇总为 `[B,256]`：

| `pooling_mode` | 汇总方式 | 首版用途 |
| --- | --- | --- |
| `dot_product` | 单个可学习查询的缩放点积汇总 | 默认 |
| `mha` | 单个可学习查询作为 Query、对象表示作为 Key/Value 的 4 头 MHA | 可选 |

点积汇总定义为：

```text
score_i = q_pool · H_i / sqrt(256)
weight = masked_softmax(score)
pooled_context = Σ weight_i × H_i
```

MHA 路由的注意力 Dropout 为 0.1。两种路由都屏蔽 PAD，并保持集合重排不改变结果。`pooling_mode` 在训练前固定并写入检查点，训练中不切换；06 必须沿用相同路由。

汇总向量拼接 `time_sin`、`time_cos` 后，经 `Linear(258,256)` 得到整体需求状态。全部输入为 PAD 时跳过汇总，直接使用全 0 汇总向量。

### 2.4 查询与融合头

整体需求状态分别进入三个输出头：

```text
static_query = normalize(Linear_static(state))
history_query = normalize(Linear_history(state))
fusion_weights = softmax(Linear_fusion(state))
```

两路查询使用 `eps=1e-12` 的安全 L2 归一化；`fusion_weights[0]`、`fusion_weights[1]` 依次为静态和历史权重。融合权重通过排序损失学习。两种汇总路由的参数量为：

| 汇总路由 | 状态编码器 | 三个 Actor 输出头 | Actor 总计 |
| --- | ---: | ---: | ---: |
| `dot_product` | 2,242,048 | 66,306 | 2,308,354 |
| `mha` | 2,505,216 | 66,306 | 2,571,522 |

参数量不包含冻结的 03/04 模型。

### 2.5 检索得分

```text
s_static(i) = static_query · static_vector(i)
s_history(i) = history_query · history_vector(i)
s_fusion(i) = fusion_weights[0] × s_static(i)
            + fusion_weights[1] × s_history(i)
```

查询和对象向量均已 L2 归一化，内积等价于余弦相似度。历史向量无效时令 `s_history=0`。

```text
静态 Exact Top-256
+ 历史 Exact Top-256
→ 合并去重，最多 512 个对象
→ 记录持久索引的历史得分、融合得分和 revision
```

候选集合由持久索引固定。05 自然评价按当前 `t` 临时刷新全部并集候选，再按当前融合得分稳定重排并截取 Top-256；06 接收最多 512 个并集候选，先执行不依赖 04 当前预测的廉价 Mask，再只刷新剩余候选。临时刷新只更新历史与融合得分，不回写索引。

每个完成临时刷新的候选至少保留 `static_score`、`retrieval_history_score`、`retrieval_fusion_score`、`current_history_score`、`current_fusion_score`、`history_revision` 和 `candidate_as_of_time`，不得用一组含义不明的 `candidate_scores` 覆盖两种版本；06 中被廉价 Mask 的候选后两项当前得分和时间为空。得分相同时按 `path_index` 升序。静态索引覆盖全部合法对象，历史索引只覆盖当前 24 小时活跃且版本有效的对象。首版固定两路各 Top-256，不比较其他数量。

后续可尝试拼接空间的全局融合检索或扩大初始 Top-K；本轮不实现，也不改变上述合同。

## 3. 训练目标

05 冻结 03 静态模型和 04 动态历史模型，只更新 Actor。对每个训练正对象 `p` 及其负对象 `n`，分别计算静态、历史和融合得分。

单个正负样本对的排序损失统一为：

```text
pair_loss(s_p, s_n) = softplus(s_n - s_p)
```

### 3.1 静态排序任务

```text
L_static_pair
= softplus(s_static(n) - s_static(p))
```

所有合法正负样本对都参加静态排序。该任务要求 Actor 的静态查询在 03 静态向量空间中靠近未来需求对象并远离历史活跃负对象。

### 3.2 历史排序任务

```text
L_history_pair
= softplus(s_history(n) - s_history(p))
```

只有正、负对象两端的历史向量都有效时才计算历史排序。某个截点没有有效历史样本对时，该截点的历史损失为 0，不影响另外两路训练。

`L_history` 的正负对象都读取截点 `t` 已发布的持久历史索引向量，用来拟合运行时第一阶段历史 Top-256 召回；不得混入候选临时刷新向量。

### 3.3 融合排序任务

```text
L_fusion_pair
= softplus(s_fusion(n) - s_fusion(p))
```

融合排序覆盖全部合法正负样本对。正负对象均按当前截点 `t` 调用 05 上游适配器的只读 `encode_as_of` 接口；适配器从 05 滚动访问状态提取 `access_time < t` 的对象历史，批量调用冻结的 04 编码器，再与静态向量计算融合得分，用来拟合运行时候选重排。历史缺失对象的历史得分按 0 处理，使 Actor 学习在不同状态下分配静态和历史权重。该接口不得推进事件游标、修改滚动访问状态、写回持久索引或改变 `history_revision`。

### 3.4 分层加权与总损失

未来需求按四个提前量层组织。每一路损失按以下顺序汇总：

1. 对一个正对象分配到的有效负对象损失求平均；
2. 乘以该正对象的采样权重；
3. 在同一提前量层内按正对象采样权重之和归一化；
4. 对当前截点存在有效样本的提前量层等权平均；
5. 对一个批次中的有效截点等权平均。

监督总损失为：

```text
L_supervised = L_static + L_history + L_fusion
```

三项首版等权。没有未来正样本的截点不产生监督损失，但仍保留在自然时间数据中，用于连续更新历史索引。

训练按轮记录 `L_static`、`L_history`、`L_fusion`，三路正样本得分高于负样本的比例、历史有效样本对比例，以及静态/历史融合权重的均值和分布。这些指标只用于诊断，不改变固定20轮训练，也不读取测试集。

## 4. 样本构造与切分

### 4.1 连续因果回放

首版决策间隔为 10 秒，并作为配置写入数据 manifest。每个截点 `t` 严格按以下顺序处理：

```text
消费 access_time < t 的新增事件，更新 05 滚动访问状态、活跃对象和 dirty 集合
→ 删除 24 小时过期对象并选择 Actor 上下文
→ 按 1.2 分层刷新持久索引并发布 revision
→ 构造并保存 Actor 状态
→ 通过独立时间索引查询 [t,t+1h) 标签并完成正负采样
→ 对采样对象执行只读 encode_as_of(t)，生成融合训练向量
```

`access_time=t` 不得进入当前状态，但可以进入 `[t,t+1h)` 标签；标签查询不得推进主回放游标或修改冻结在 `t` 的滚动访问状态。所有时间按 Asia/Shanghai 解释。

04 参数全程冻结。持久索引更新严格复用 1.2，并由 05 数据生成、自然评价和 06 共同实现。`L_history` 读取当前 revision 的持久向量；`L_fusion` 使用只读临时向量。两者均不得读取 `access_time >= t` 的历史，临时结果不得回写索引或影响后续截点。

### 4.2 上下文对象

每个截点最多选择 256 个不同对象：

```text
最近访问 128 个 + 最近 1 小时热门对象补齐至 256 个
```

规则如下：

- 最近访问集合按最后访问时刻从近到远选择 128 个不同对象；同一秒时按 `path_index` 从小到大确定顺序。
- 一小时热门对象按 `[t-1h,t)` 内访问次数从高到低排序；次数相同时按最后访问时刻从近到远，再按 `path_index` 从小到大排序。
- 最近访问集合优先放入。热门对象与最近集合重合时不重复，但最近对象标记和一小时热门标记都置为 1，并继续扫描热门排序直至补满或列表耗尽。
- 真实对象不足 256 个时用 PAD 补齐。

实现时使用按时间排序的一小时事件队列和 `path_index → (访问次数, 最后访问时刻)` 滚动表：每个截点只加入本轮新增事件并移除 `access_time < t-1h` 的事件，计数归零后删除对象，禁止每 10 秒重新扫描一小时日志。

对象排列只用于确定性落盘，不承载访问顺序语义。

### 4.3 正样本

未来 1 小时内至少访问一次的不同对象构成完整正样本集合。每个对象按首次需求距截点的时间落入一个互斥层：

| 提前量层 | 首次需求时间 |
| --- | --- |
| 即时需求 | `[t,t+5s)` |
| 短期需求 | `[t+5s,t+30s)` |
| 中期需求 | `[t+30s,t+5min)` |
| 提前需求 | `[t+5min,t+1h)` |

正样本不按缓存、在途、对象大小、通道或队列过滤。四层表示“何时可能需要”，不表示对象在 06 的当前资源状态下一定来得及完成。

每个截点最多使用 96 个训练正对象：

1. 完整正样本不超过 96 个时全部参加训练，采样权重为 1；
2. 超过 96 个时，四层首版各分配 24 个目标名额；
3. 某层不足时保留全部对象，并按其他层剩余对象数使用最大余数法重分配空余名额；
4. 每层先保留未来窗口内访问次数最高的最多 8 个对象，次数相同时按 `path_index` 从小到大；
5. 其余名额使用固定种子无放回抽样，并记录逆入选概率权重。

对某层，设完整对象数为 `N`、最终名额为 `q`。若 `N<=q`，全部权重为 1；否则确定性保留 `h=min(8,q)` 个对象并令其权重为 1，再从其余 `N-h` 个对象抽取 `r=q-h` 个，随机入选对象权重为 `(N-h)/r`。

`positive_folder_ids_all` 必须保留未来 1 小时完整正样本集合和首次需求层，供自然评价及负样本排除使用。随机种子由全局种子和截点共同确定，使并行生成、失败重试和重新发布得到相同结果。

### 4.4 负样本

负样本从对象主表中静态向量有效、且不属于未来 1 小时完整正样本集合的对象中选择：

| 层级 | 最近一次访问距今 | 总体目标比例 |
| --- | --- | ---: |
| 近期困难负样本 | 5 分钟内 | 45% |
| 中期负样本 | 5 分钟至 1 小时 | 27% |
| 长期负样本 | 1 小时至 24 小时 | 18% |
| 全局冷负样本 | 24 小时内未访问 | 10% |

每个训练正对象最多分配 3 个负对象。一个截点的总配额按 45%/27%/18%/10% 使用最大余数法取整；某层不足时保留全部对象，再按其他层剩余池大小使用最大余数法补齐。前三层合计 90%，其内部仍保持原 50%/30%/20% 的活跃负样本结构；全局冷负样本用于覆盖静态检索面对的全对象空间。

各层使用固定种子无放回抽样。采样后的负对象固定种子打乱，训练正对象按首次需求时间、`path_index` 排序后轮转分配，每个最多 3 个；全部合法负对象不足时按实际数量生成。负样本比例是有意设置的训练分布，不使用逆概率权重；必须记录各层池大小、实际抽样数和来源。

模型召回困难负样本作为后续候选但首版不执行：可使用首轮 Actor 在训练截点执行双路 Exact 检索，从高分但不属于完整正样本集合的对象中回灌负样本。启用时只能使用训练段，必须发布新数据版本并重新训练，禁止修改原样本或从测试段挖掘。

### 4.5 时间切分

首版只有训练集和测试集；预热段只初始化状态，不属于数据集：

```text
[2026-06-18 00:00:00, 2026-06-19 00:00:00)：预热
[2026-06-19 00:00:00, 2026-06-24 00:00:00)：训练集
[2026-06-24 00:00:00, 2026-06-25 00:00:00)：测试集
```

预热结束时为过去 24 小时活跃对象生成初始历史索引。训练与测试之间不重置 05 滚动访问状态、活跃集合或历史索引。

只有满足 `t+1h <= 当前切分结束时间` 的截点才生成监督样本。训练末尾不足1小时的截点标记为 `transition`，测试末尾不足1小时的截点标记为 `tail`；两者只推进状态，防止训练标签进入测试集或测试观察窗口不完整。

模型结构、训练配置和采样规则在训练前固定。测试集不参与梯度、早停、轮次选择或调参；固定20轮训练结束后，只对最终检查点运行一次测试损失和自然召回。时间边界或方案配置变化必须生成新版本。

### 4.6 样本文件

正式文件为 `actor_samples.parquet`、`actor_history_snapshots.parquet`、`initial_history_index.npz` 和 `actor_samples_manifest.json`。

`actor_samples.parquet` 每个截点一行，字段按以下四组保存：

```text
标识：sample_id, cutoff_time, split, history_snapshot_id, history_revision
上下文：context_folder_ids[256], context_valid_mask[256], 两个来源标记, time_sin, time_cos
索引增量：removed_ids, updated_ids, dirty/context/recent/long/crossing_refresh_ids
监督：全部及采样正对象、需求层、采样权重、负对象、负样本来源及四层池大小/抽样数
```

`actor_history_snapshots.parquet` 与样本表同行、同 row group，并分开保存：

```text
persistent_folder_ids[], persistent_history_vectors[], persistent_history_valid[]
fusion_current_folder_ids[], fusion_current_history_vectors[], fusion_current_history_valid[]
fusion_candidate_as_of_time
```

第一组供持久索引增量和 `L_history` 使用，第二组仅供 `L_fusion` 使用，禁止混用或回写索引。历史向量以 `float16` 落盘，加载后转为 `float32` 并重新归一化；静态向量只通过 `path_index` 查询全局矩阵。

`initial_history_index.npz` 保存预热结束时的对象、历史向量、事件/编码/下次刷新时间、revision 和 `snapshot_time`。所有大文件先写隐藏构建目录，完成哈希校验后原子发布版本，最后更新 manifest 指针。

### 4.7 自然召回评价

#### 4.7.1 评价流程

测试从初始历史索引开始按自然时间顺序重放；训练与过渡段只推进索引，进入测试段后才累计指标：

```text
应用本行删除与持久索引增量
→ Actor 生成两路查询和融合权重
→ 静态、历史各 Exact Top-256，合并为最多 512 个对象
→ 按持久索引融合得分取 Top-256
→ 临时刷新全部并集候选，按当前融合得分取 Top-256
→ 与未来需求集合比较
```

临时刷新只读取 `access_time < t`，不改变候选集合、滚动访问状态或持久 revision。05 不应用缓存、在途、容量或队列 Mask，也不根据标签扩大候选集合。

| 候选类型 | 上限 | 用途 |
| --- | ---: | --- |
| `static_top256` | 256 | 静态单路 |
| `history_top256` | 256 | 历史单路 |
| `retrieval_fusion_top256` | 256 | 持久索引融合 |
| `current_fusion_top256` | 256 | 临时刷新后融合 |
| `union_pool` | 512 | 双路候选池覆盖上限 |

`union_pool` 不与 Top-256 结果作同规模比较；持久融合与当前融合的差值用于衡量临时调用 04 的收益。

#### 4.7.2 评价时域与基线

| 时域 | 区间 | 定位 |
| --- | --- | --- |
| 5 秒 | `[t,t+5s)` | 紧急需求诊断 |
| 10 秒 | `[t,t+10s)` | 对齐决策周期 |
| 30 秒 | `[t,t+30s)` | 短期诊断 |
| 5 分钟 | `[t,t+5min)` | 主要指标 |
| 1 小时 | `[t,t+1h)` | 主要指标 |

5 秒不作为预取效果门槛；另附四个互斥首次需求层结果。非学习基线为“最近访问 256 个对象”和“最近 1 小时热门 256 个对象”。

#### 4.7.3 指标与汇总

对截点 `t` 和时域 `H`，令 `P(t,H)` 为未来不同对象集合，`R(t,H)` 为未来请求事件集合，`C_t` 为候选集合：

```text
对象 Recall = |C_t ∩ P(t,H)| / |P(t,H)|
请求覆盖 = Σ[r∈R(t,H)] 1[path_index(r)∈C_t] / |R(t,H)|
字节覆盖 = Σ[r∈R(t,H)] total_size_bytes(r)×1[path_index(r)∈C_t]
           / Σ[r∈R(t,H)] total_size_bytes(r)
```

每种候选、每个时域均报告微平均和宏平均：

```text
natural_<type>_object_recall_micro/macro
natural_<type>_request_coverage_micro/macro
natural_<type>_byte_coverage_micro/macro
```

微平均先累计分子和分母，宏平均先逐截点计算再等权平均。空目标截点不进入三项宏平均，但必须推进历史，并单独报告比例。附加诊断包括：目标对象数超过 256 的截点比例、`union_pool` 数量分布、历史索引规模、各类刷新数量与陈旧度，以及临时刷新前后的得分和排名变化。

#### 4.7.4 输出与性能

- `natural_recall_test.json`：汇总测试损失、自然召回、空目标比例、新鲜度和耗时。
- `natural_candidates_test.parquet`：保存 `cutoff_time`、`path_index`、召回来源、两套得分与排名、`history_revision` 和 `candidate_as_of_time`。

Exact 检索和候选临时编码必须批量执行；报告总耗时、每截点编码数量及链路耗时的均值、P50、P95和最大值，不得降低 10 秒评价频率。采样损失和排序准确率只作训练诊断；后续 ANN 必须在相同查询、revision 和 Top-K 下报告相对 Exact 的召回损失与延迟。

## 5. 训练过程

### 5.1 运行顺序

```text
校验 02/03/04 正式输入
→ 构建静态向量库和一天预热后的初始历史索引
→ 连续因果回放并发布监督数据版本
→ 从 manifest 加载不可变样本
→ 只读取训练集，固定训练 4 层 Actor 20轮
→ 发布第20轮正式检查点
→ 训练结束后对正式检查点运行一次测试损失与自然召回
```

### 5.2 首版固定配置

| 参数 | 值 |
| --- | ---: |
| Transformer 层数 | 4 |
| 优化器 | AdamW |
| 学习率 | `1e-4` |
| 权重衰减 | `1e-4` |
| Batch Size | 32 |
| 固定轮次 | 20 |
| 梯度裁剪范数 | `1.0` |
| 学习率调度 | 不使用 |
| 混合精度 | 首版关闭 |
| 打乱缓冲区 | 4096 个截点 |

随机种子由配置固定并写入检查点。Batch 32 若在正式训练前的 Docker 预检中内存不足，可改小后重新冻结配置；正式运行中不得自动改变。首版不搜索上述参数。

### 5.3 数据加载与损失

训练集按固定种子使用 4096 行有限缓冲区打乱；只能打乱已构造样本，不能打乱日志后重建状态。测试集在训练过程中不得创建 DataLoader 或参与任何计算；训练结束后的测试保持自然顺序。两张 Parquet 按同行、同 row group 流式联读，不将全部历史快照载入内存。

一个训练 Batch 只有 `L_history` 无有效对时令其为 0，另外两路正常训练；三路都无有效对时跳过反向传播和优化器更新。

测试只运行一次，不能用于选择检查点。测试损失严格复用 4.4 的“层内按采样权重归一化、有效提前量层等权、有效截点等权”规则，在全测试集累计三项任务损失；任一任务在整个测试集没有有效样本对时终止运行并报告数据错误。

### 5.4 固定轮次与恢复

首版固定完成20轮，不设置Early Stopping，不保存或选择“最佳验证轮次”。第20轮保存为 `actor_supervised_final.pt`，测试只对该文件运行一次，测试结果不得反向改变结构、样本、轮次或 Top-K。

`actor_supervised_last.pt` 每轮原子更新，并保存模型、优化器、轮次、随机数状态、数据加载器状态及配置；恢复训练后必须得到与不中断运行一致的后续样本顺序。只有恢复并完成第20轮后才能发布正式检查点。

输入、损失或梯度出现非有限值时立即停止，并记录轮次、Batch 和 `sample_id`，禁止跳过异常继续训练。困难负样本回灌首版不执行；后续启用时必须发布新数据版本并重新训练。

## 7. 验收

验收分为五项：

1. **向量库构建：** 05 能从 02 数据和 03/04 模型制品生成覆盖全部对象的静态向量库及一天预热后的初始动态索引；对象映射、维度、归一化和 SHA256 全部闭合。
2. **数据因果与索引新鲜度：** 当前状态及临时编码读取 `access_time >= t` 事件的数量为 0；dirty 对象超过 10 秒、近期层对象超过 300 秒、长期层对象超过 3600 秒仍未刷新的数量均为 0；跨入长期层的对象均在边界轮刷新；候选和融合训练临时编码不改变持久 revision；`L_history` 与 `L_fusion` 使用的向量版本可区分且可重放；正对象唯一落入一个首次需求层；负对象与完整未来正样本集合无交集；相同输入、配置和随机种子得到相同样本、历史 revision 和 manifest。
3. **模型接口：** 独立加载第20轮正式检查点后，能够从 `[B,256,259]` 对象输入、有效掩码和时间特征生成两路 128 维归一化查询及有效融合权重；第一版固定 4 层，`dot_product` 和 `mha` 路由参数量分别为 2,308,354 和 2,571,522，实际参数量必须与检查点中的 `pooling_mode` 一致；对象集合一致重排后输出在容差内不变。
4. **首版效果报告：** 确认训练过程读取测试样本数为0，并在训练结束后完整报告测试集上的静态、历史、并集、双路截断融合和两项非学习基线在 5 秒、30 秒、5 分钟和 1 小时上的目录 Recall、请求次数加权覆盖和字节加权覆盖。测试结果不得用于反复调参，也不宣称达到尚未冻结的上线门槛。
5. **交付一致性：** 向量库、样本、历史快照、初始索引、manifest 和检查点能够相互追溯；06 能够复用相同状态构造、历史索引、归一化和候选融合合同，无歧义地生成相同 Actor 输出及双路各 Top-256、合并最多 512 个的自然候选。
