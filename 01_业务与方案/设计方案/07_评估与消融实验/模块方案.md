# 07 评估与消融实验模块方案

## 定位

07 统一验证 02—06 的正确性、效果和增益来源。该模块只读取冻结制品和检查点，不参与训练或阈值选择。当前端到端方案没有独立测试集，因此结果统一表述为验证结论。

## 评估层次

| 层次 | 核心问题 |
| --- | --- |
| 数据与语义 | 对象、字段、时间和版本是否正确 |
| 单向量 | 03/04 是否分别学到静态关系和短期需求 |
| 候选召回 | 05 双路融合能否覆盖未来真实对象 |
| 执行策略 | 06 是否在 LRU 与取回约束下提高双命中率且控制副作用 |
| 系统边界 | 收益是否依赖目录代理、通道数、带宽或特定流量日 |

## 必备对照

1. 3%容量、30通道 × 200 MiB/s无预取按需 LRU 方法验证主基线，以及10通道真实约束参考；60通道只在30通道可训练性检查失败时作上限诊断。
2. 最近访问、过去窗口热度和单位容量热度等简单策略。
3. 仅静态查询、仅历史查询、固定权重融合和 Actor 动态融合。
4. Actor 候选上的简单分数贪心：按“完成后访问概率 × 对象字节数”选择。
5. 通过环境与长期价值门槛后的 Actor-Critic 策略。

第 1 项可复用 02 结果进行黄金对账；第 4 项会主动提交预取，虽然仍采用 LRU 淘汰，但必须在 06 中单独回放，不能用 02 的无预取 LRU 代替。

约束贪心和短程 Rollout 不作为首轮必备对照；只有首轮相对无预取和简单分数贪心已有增益时，再按独立评估配置补充。

瞬时回填和固定 5/10 秒 LRU 只作为理想延迟对照，不与有限带宽策略作不加说明的同口径优劣比较。

## 主指标

**召回层。** Recall@K、MRR/NDCG、静态/历史并集覆盖、融合增益、候选上限不足率、近似 ANN 相对 Exact 的 Recall 与延迟。

**缓存层。** 字节命中率为首要指标，读取次数命中率必须共同报告；两者均给出相对同环境无预取基线的绝对提升和相对提升。

**执行与预取层。** 平均等待、P50/P95/P99 等待、等待请求秒总和、物理取回数、读取字节、排队/服务中合并数、通道利用率、队列峰值、预取对象数与字节、有效预取率、未使用淘汰率、流量放大、额外淘汰 Miss 和受害对象等待。

**正确性。** 硬约束违规数、奖励对账误差、始终 STOP 差异数、版本或哈希不一致数。

硬约束是先决条件；通过硬约束和预先登记的副作用边界后，以字节命中收益为主、读取次数命中收益为次选择策略。等待、额外读取和污染必须完整报告，但不能替代双命中率结论。

## 消融矩阵

- **静态侧：** 仅共享语义、仅实例、不同语义/实例权重、去掉属性辅助任务。
- **历史侧：** 去掉短期/中期/长期任一时间尺度，改变困难/中等/简单负样本比例，去掉排序任务。
- **Actor：** 静态单路、历史单路、固定融合、动态融合，改变上下文规模和 Transformer 层数。
- **检索：** Top-K、Exact 与近似 ANN、索引刷新频率、24 小时过期删除。
- **策略：** 简单分数贪心、Critic 不更新 Actor、去掉 05 锚定、不同 STOP 探索覆盖；首轮有增益后可选补充约束贪心和短程 Rollout。
- **环境：** 首版固定3%容量、200 MiB/s和10秒决策周期，每宏步最大预取数是可配置环境超参数且首轮默认2；30通道用于验证方法，10通道用于解释真实资源瓶颈，60通道仅诊断方法在更宽松带宽下是否存在信号。不同场景不得共用Replay或Critic。

一次消融只改变一个受控因素，其余数据版本、日期切分、随机种子、候选上限和环境合同保持一致。

## 统计与分组

- 验证日期用于配置、检查点和方案比较，所有选择过程必须留痕。
- 同时报告逐日结果与全验证段按请求加权结果，不表述为独立测试结论。
- 按高峰/非高峰、对象大小、访问热度、首次观察/淘汰后 Miss、排队/服务状态和路径质量层分组。
- 保存每次运行的配置、检查点摘要、源制品摘要、代码版本、随机种子和原始指标账本。
- 对关键策略使用多随机种子；报告均值、离散程度和最差种子，不只展示最佳运行。

## 输出规划

```text

├── config/          冻结评估矩阵
├── scripts/         统一运行入口
├── src/             指标、分组、对账与报告生成
├── tests/           指标恒等式和最小回放测试

    ├── manifests/   每次评估的版本清单

    └── reports/     正式 Markdown 与图表
```

字段名和目录在真正编码时再由实现固定；自行创建的字段使用中文，不预先制造与未来代码不一致的英文键名。
