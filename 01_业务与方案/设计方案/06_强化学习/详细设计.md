# 06 强化学习详细设计

本设计说明 06 如何复用 05 的监督 Actor，在有限通道和 LRU 缓存环境中训练 Critic，并用长期优势继续更新 Actor。实现以[模块方案](模块方案.md)、[05 详细设计](../05_监督微调/详细设计.md)和[业务约束](../../业务约束.md)为准。

## 2. 有限资源事件环境

### 2.1 取回任务与通道

环境包含需求任务和预取任务，两者进入同一个 FIFO 并竞争同一组通道。每个任务至少保存：

```text
path_index, source, submit_time, start_sequence
total_size_bytes, service_start_time, ready_time
waiting_requests[]
```

无排队服务时间为：

```text
service_seconds = fixed_setup_seconds
                + total_size_bytes / bandwidth_bytes_per_second_per_channel
```

一个任务独占一个通道直至完成。空闲通道按通道编号从小到大领取 FIFO 队首，`start_sequence` 全局递增，用于稳定处理同一时刻完成的任务。

请求到达时按以下规则处理：

1. 对象已完整缓存：记 Hit，并移动到 MRU；
2. 对象已排队或传输：请求合并到原任务，不创建重复任务，也不记 Hit；
3. 其他情况：创建需求任务并进入 FIFO。

真实请求合并到预取任务后不改变原任务的 FIFO 位置和优先级；请求继续等待，预取完成后该次访问记为有效预取，但不记 Hit。

每条逻辑请求单独记录 Hit、对象字节数和从到达到对象可用的等待时间。

### 2.2 缓存与 LRU

- 对象完整取回前不能命中，也不能更新 LRU；
- 任务完成时对象进入 MRU；空间不足时从 LRU 端连续淘汰；
- 单个对象大于缓存容量时，需求任务仍提供读取服务，但完成后不写缓存；
- 超大对象不得成为预取动作；
- 预取对象完成后，只有在淘汰前被真实请求访问才记为有效预取。

策略环境和无预取基线环境从相同快照开始，之后独立维护缓存、LRU、FIFO、通道、在途任务和账本。基线环境永不预取，也不得进入 Actor 或 Critic 输入。

### 2.3 决策周期与事件顺序

环境通过唯一的 `advance_to(target_time)` 接口按时间顺序处理尚未消费的任务完成和真实请求，任何事件只能处理一次。决策时刻 `t` 的状态只能使用 `access_time < t` 的请求；固定顺序为：

```text
advance_to(t)
→ 发布 history_revision 并构造 05 Actor 状态
→ 运行 Actor 和双路检索
→ 执行不依赖 04 当前预测的廉价 Mask
→ 仅临时刷新剩余候选，再执行动态 Mask 和策略路由
→ advance_to(t + decision_latency)
→ 在 t + decision_latency 按选择顺序重新校验并提交仍合法的预取任务
→ advance_to(t + decision_interval)
→ 结算宏步奖励
```

`advance_to(t)` 处理 `ready_time <= t` 的任务完成和 `access_time < t` 的请求：同一秒内先按 `start_sequence` 处理完成任务，再按日志原始顺序处理请求。`access_time=t` 的请求不能进入当前状态，而是在本周期后续推进时处理。动作提交前只重新执行确定性 Mask，不重新运行 Actor 或 Critic；失效动作直接丢弃，不补选其他候选。

持久索引严格复用 05 的分层合同：dirty 和 Actor 上下文立即刷新，近 1 小时层最多 300 秒、1～24 小时层最多 3600 秒，对象跨过 1 小时边界立即刷新，超过 24 小时删除。各来源通过确定性的 `next_refresh_time` 合并去重后批量编码；仅持久刷新或删除可以使 `history_revision` 递增。

模拟决策耗时覆盖状态构造、Actor、两路检索、廉价 Mask、04 候选刷新和策略推理；训练与测试均使用配置中的固定值，不读取程序实际运行耗时。

### 2.4 快照与时间切分

时间边界直接读取 05 manifest，不在 06 重新划分：

1. 从访问日志起点以无预取方式 burn-in 到 05 的 `snapshot_time`；
2. 分别为 10、30 通道保存独立初始环境快照；需要时再生成 60 通道快照；
3. 测试环境从初始快照继续按无预取推进到测试起点；
4. 所有测试策略从同一个测试快照克隆；
5. 训练段和测试段最后一小时只允许 STOP，用于完成在途任务和奖励结算。

环境快照至少保存当前时间、日志读取位置、缓存对象及 LRU 顺序、FIFO、通道任务、在途任务和统计账本。

04 滚动历史可跨切分连续推进，但训练 Replay 不能读取测试段。05 manifest 只定义训练集和测试集，不设置验证集；测试段只在训练完成后运行一次，不参与梯度、早停、检查点选择或策略调参。

## 3. 候选与策略

### 3.1 自然候选

每个决策时刻只运行一次 Actor：

```text
静态查询 × 全量静态向量 → Exact Top-256
历史查询 × 当前历史索引 → Exact Top-256
两路合并去重 → 最多 512 个自然候选
记录持久索引的召回分数与 history_revision
→ 执行廉价 Mask
→ 仅对未 Mask 候选按当前 t 批量刷新历史向量和时间分布
→ 计算当前历史得分、融合得分和 Critic 特征
```

完整并集不按融合 Top-K 再截断。两路重合对象只保留一次，得分相同时按 `path_index` 升序。候选集合生成后，本宏步内不得再次调用 Actor 或检索索引。廉价 Mask 命中的对象保留在轨迹中用于审计，但不调用 04，也不进入 Critic 合法候选集合。

每个候选记录以下版本明确的字段：

```text
path_index, static_score
retrieval_history_score, retrieval_fusion_score
current_history_score, current_fusion_score
history_revision, candidate_as_of_time
mask_reason
```

`retrieval_*` 使用生成 Top-256 时的持久索引向量；`current_*` 使用当前 `t` 临时编码的向量。廉价 Mask 对象的 `current_*` 和 `candidate_as_of_time` 为空。临时编码调用 04 的只读 `encode_as_of`，只读取 `access_time < t`，不得推进事件游标、修改滚动状态、写回持久索引或产生新 revision。

静态路候选缺少持久历史向量时，`retrieval_history_score` 按 0 参与融合；临时刷新后仍缺少有效 04 输出时，由动态 Mask 排除。

首版使用 Exact 内积。后续改用 ANN 时必须形成新检索版本，并报告相对 Exact 的候选损失。

### 3.2 完成后访问概率与 Mask

04 为候选输出未来一小时首次访问时间分布。概率下标0～8对应边界`[0, 5, 10, 30, 60, 120, 300, 600, 1800, 3600]`秒形成的9个前闭后开区间，下标9表示未来一小时无访问。影子环境给出候选完成距今时间 `d`：

- `d < 0` 按 0 处理；
- `0 <= d < 3600` 时，完整时间档直接累加，完成时刻所在档按档内均匀分布拆分；
- `p_after_completion = p_access_within_1h - p_before_completion`；
- `d >= 3600` 时标记超出预测范围并 Mask。

廉价 Mask 在调用候选 04 推理前执行，包括：

- 已缓存、已排队/服务中或已在当前影子批次中；
- 对象无效、大小无效、必需静态向量或对象映射缺失；
- 对象大于缓存容量；
- 依据当前 FIFO、对象大小和通道最早可用时刻的完成下界，已可确定一小时内无法完成；
- 完成下界晚于当前计分终点；
- 当前处于切分末尾隔离结算区。

候选临时刷新后及每个影子动作后，再根据更新后的 FIFO、通道和完成时刻执行动态 Mask；04 当前输出缺失或非有限、完成距今 `d >= 3600`、预计完成晚于计分终点、已被同批选择或已达到 `max_prefetch_per_macro_step` 时不可选择。

Mask 由环境执行，不通过负奖励学习。无合法候选时只允许 STOP。

### 3.3 影子批次与 STOP

候选选择不立即修改真实环境。影子环境从决策时刻 `t` 复制当前状态，只推进当时已知任务至预计动作提交时刻 `t + decision_latency_seconds`，不得读取 `access_time >= t` 的真实请求。每选择一个候选后依次更新：

1. 影子 FIFO 和通道可用时刻；
2. 预计排队、服务和完成时刻；
3. 预计缓存写入和 LRU 淘汰结果；
4. 剩余候选特征、当前得分和动态 Mask。

影子状态不预测本周期未来真实请求。实际结果由事件环境推进，估计误差交给 Critic 通过长期回报学习。

选择一个候选并更新影子状态后，必须使用更新后的特征和 Mask 重新运行 Critic，再决定下一个候选或 STOP；第一次计算的 Q 值不得复用于第二次选择。

两个 Critic 对全部合法候选和 STOP 同时估值，策略取较小值：

```text
Q(s,a) = min(Q1(s,a), Q2(s,a))
max(Q_candidate) > Q_stop  → 选择最高价值候选
其他情况                  → STOP
```

候选同分时按 `path_index` 升序；候选与 STOP 同分时优先 STOP。策略可选择 0、1 或 2 个对象，达到上限后强制 STOP。

### 3.4 策略路由

| 路由 | Actor | 规则 |
| --- | --- | --- |
| `no_prefetch` | 不运行 | 不生成主动预取，仅推进需求任务 |
| `simple_greedy` | 冻结监督 Actor | 选择正的最大 `p_after_completion × total_size_bytes` |
| `critic` | 冻结监督 Actor | 使用在线双 Critic 的较小值与 STOP 比较 |
| `actor_critic` | 强化 Actor | 使用与该 Actor 版本绑定的双 Critic |

简单贪心在选择第一个对象后必须更新影子状态，再计算第二个对象的完成后概率和分数。无正分候选时 STOP。`critic` 和 `actor_critic` 缺少匹配检查点时必须报错，不能静默回退。

## 4. Critic 与训练目标

### 4.1 Critic 输入

需求状态使用与实际 05 Actor 检查点相同的状态编码器配置，输入为 `[256,259]` 对象集合和两个日内时间特征，输出 256 维。Critic 编码器从监督 Actor 复制初始参数，之后独立训练。

每个微步追加 10 维资源状态，字段顺序固定为：

```text
空闲通道比例
服务中任务比例
FIFO任务数
FIFO字节 / 缓存容量
服务中字节 / 缓存容量
缓存占用比例
在途需求任务数
在途预取任务数
影子批次对象数
影子批次字节 / 缓存容量
```

每个候选使用 274 维特征：

| 特征 | 维度 |
| --- | ---: |
| 静态向量、当前历史向量 | 256 |
| 历史有效标记 | 1 |
| `static_score`、`current_history_score`、`current_fusion_score` | 3 |
| 对象大小 / 缓存容量 | 1 |
| 预计淘汰对象数、淘汰字节比例 | 2 |
| 被淘汰对象近一小时访问次数和、最小距今秒 | 2 |
| 与已选对象的最大静态余弦相似度 | 1 |
| 是否触发缓存淘汰 | 1 |
| 预计排队秒、服务秒、完成距今秒 | 3 |
| 完成前、完成后访问概率 | 2 |
| 超出一小时标记 | 1 |
| 未来五分钟预计访问次数 | 1 |
| **合计** | **274** |

表中均为原始字段。计数、秒数和可能大于 1 的非负比例统一执行一次 `log1p`，再按训练拟合段统计量标准化；向量、相似度、检索分数、概率、布尔值和 `[0,1]` 比例保持原值。任何字段不得重复变换，字段顺序、变换类型和统计量随 Critic 检查点保存，校准轨迹和测试集不得参与统计量计算。

### 4.2 Critic 网络

```text
Actor同结构状态编码器 → 需求状态[256]

资源状态[10]
→ Linear(10,64) + GELU + LayerNorm
→ Linear(64,64) + GELU + LayerNorm
→ 资源表示[64]

需求状态[256] + 资源表示[64]
→ Linear(320,256) + GELU + LayerNorm
→ Critic状态[256]

候选特征[274]
→ Linear(274,256) + GELU + LayerNorm
→ Linear(256,128) + GELU + LayerNorm
→ 候选表示[128]

已选候选表示按维mean和max拼接 → 批次表示[256]

候选头：[256 + 128 + 256]
→ Linear(640,256) + GELU + LayerNorm
→ Linear(256,64) + GELU
→ Linear(64,1)

STOP头：[256 + 256]
→ Linear(512,256) + GELU + LayerNorm
→ Linear(256,64) + GELU
→ Linear(64,1)
```

空批次的 mean/max 表示填零。所有 Linear 包含偏置，LayerNorm 包含可学习缩放和偏置。模型保存实际 05 状态编码器配置，不在 06 硬编码 Actor 层数。

使用两个参数完全独立的在线 Critic `Q1`、`Q2`，各自包含独立状态编码器和完整网络；二者从同一监督 Actor 状态编码器初始化，新增层分别使用随机种子 2026 和 2027，训练时不共享参数。每个在线 Critic 都有同结构的 Target，初始化为在线副本并分别使用：

```text
theta_target = tau * theta_online + (1 - tau) * theta_target
tau = 0.005
```

两个 Target 均不接收优化器梯度，计算 TD 目标时使用推理模式。

### 4.3 奖励与折扣

对宏步 `[t,t+10s)` 内每条逻辑请求 `i`：

```text
delta_count_i = hit_policy_i - hit_baseline_i
delta_bytes_i = total_size_bytes_i * delta_count_i

DeltaCount_t = sum(delta_count_i)
DeltaBytes_t = sum(delta_bytes_i)
```

训练段固定归一化尺度：

```text
CountScale = 训练段总请求数 / 训练段宏步数
BytesScale = 训练段请求对象字节数之和 / 训练段宏步数

r_t = 0.8 * DeltaBytes_t / BytesScale
    + 0.2 * DeltaCount_t / CountScale
```

主奖励不裁剪，以保留大对象对字节命中率的影响。选择候选的微步奖励为 0，STOP 微步获得 `r_t`。等待、额外读取、未使用预取、污染和通道占用单独记录，不重复加入主奖励。训练报告必须给出奖励的 P50、P90、P99 和最大绝对值；奖励或 TD 目标出现非有限值时停止训练并判定 Replay 无效。

候选选择不推进时间，折扣为 1。STOP 推进 10 秒：

```text
gamma_stop = 2 ** (-10 / 3600) ≈ 0.998076
```

轨迹终点折扣为 0；决策周期变化时按实际秒数重新计算。

### 4.4 Critic 损失

合法动作价值统一定义为：

```text
Q_online(s,a) = min(Q1_online(s,a), Q2_online(s,a))
Q_target(s,a) = min(Q1_target(s,a), Q2_target(s,a))
```

候选微步不推进时间，使用一步目标：

```text
a_star = argmax_a Q_online(s_next,a)
y = Q_target(s_next,a_star)
```

STOP 推进宏步，默认累计未来 `n_step=6` 个宏步奖励：

```text
G_t = sum(k=0..n-1, gamma_stop^k * r_(t+k))
a_star = argmax_a Q_online(s_(t+n),a)
y = G_t + gamma_stop^n * Q_target(s_(t+n),a_star)
```

不足 `n_step` 就到达轨迹终点时截断累计且不 bootstrap。`n_step=1` 时退化为一步 TD。两个在线 Critic 使用同一目标独立更新：

```text
L_critic = 0.5 * (
    Huber(Q1_online(s,a), y)
  + Huber(Q2_online(s,a), y)
)
```

首版训练参数为：

| 参数 | 默认值 |
| --- | ---: |
| 优化器 | AdamW |
| 学习率 | 0.0001 |
| 权重衰减 | 0.0001 |
| 每批宏步数 | 128 |
| Huber delta | 1.0 |
| 梯度裁剪 | 1.0 |
| Target Polyak 系数 | 0.005 |
| 多步回报 `n_step` | 6 |
| 初始 Critic 最大更新次数 | 10000 |
| 混合 Replay 最终 Critic 最大更新次数 | 20000 |
| 校准间隔 | 500 次更新 |
| 早停耐心 | 5 次校准 |
| 抽样随机种子 | 2026 |

默认取训练段结束前第 7 至第 1 小时作为 6 小时内部校准段，最后 1 小时仍只用于在途结算。先用固定行为策略和随机种子生成一次校准 Replay，保存固定状态、动作和从该 transition 到轨迹终点的折扣回报 `G_fixed`；该 Replay 不参与梯度且不得来自测试集。每 500 次更新在同一校准 Replay 上报告 `abs(min(Q1_online,Q2_online)-G_fixed)` 的 MAE 和 P90，MAE 连续 5 次未改善时早停并恢复 MAE 最小的检查点。

恢复最佳 Critic 后，再在相同 6 小时时间范围从同一起点运行一次冻结贪心策略，报告实际累计奖励、双命中差分和副作用，并在这条最终策略轨迹上计算 Q 校准误差 P90。该 P90 作为 `advantage_margin`；未完成最终策略回放和校准时不得生成 Actor 优势标签。上述最大更新次数分别作用于每个 Actor 版本的初始 Critic 阶段和混合 Replay 最终 Critic 阶段。

### 4.5 Actor 强化更新

对宏步初始状态中的自然候选计算：

```text
A_t(c) = min(Q1_target(s_t,c), Q2_target(s_t,c))
       - min(Q1_target(s_t,STOP), Q2_target(s_t,STOP))
```

使用 4.4 最终策略轨迹的 Q 校准误差 P90 作为 `advantage_margin`：

- `A_t(c) > advantage_margin`：正候选；
- `A_t(c) <= 0`：负候选；
- 中间区间：不生成 Actor 排序对。

Actor 复用 05 的静态、历史和融合三路成对排序损失：

```text
L_adv = L_adv_static + L_adv_history + L_adv_fusion
L_actor = L_adv + lambda_anchor * L_05_supervised
lambda_anchor = 1.0
```

每个宏步将正候选按优势降序、负候选按优势升序排列；每个正候选先与最低优势负候选配对，再用固定种子从其余合法组合补充，每个宏步最多保留 16 个不重复排序对。首版 Actor 强化参数为：

| 参数 | 默认值 |
| --- | ---: |
| 优化器 | AdamW |
| 学习率 | 0.00001 |
| 权重衰减 | 0.0001 |
| 每批宏步数 | 128 |
| 最大更新次数 | 5000 |
| 校准间隔 | 250 次更新 |
| 早停耐心 | 5 次校准 |
| 每宏步最大优势对数 | 16 |
| 梯度裁剪 | 1.0 |

Actor 使用固定的训练段优势校准对监控 `L_actor`，连续 5 次无改善时恢复最小损失检查点。没有有效优势对的 batch 跳过反向传播且不增加更新计数。每个 Actor batch 同时读取 05 锚定样本计算 `L_05_supervised`。

03、04 始终冻结。Actor 只更新状态编码器和三个输出头，输入字段、输出维度、归一化和融合语义不变。强化后字节加权、请求加权和普通目录自然 Recall 相对下降分别不得超过 0.5%、2% 和 3%。

## 5. Replay 与训练过程

### 5.1 Replay

Replay 模式版本为 `folder-rl-replay/v1`，以完整宏步为发布和抽样单位。每条记录至少包含：

```text
运行与时间：run_id, macro_step_id, cutoff_time, split
上游版本：Actor、03、04、05、环境配置摘要
Actor输出：两路查询、融合权重、history_revision
候选：path_index、特征、static_score、retrieval_history_score、retrieval_fusion_score、current_history_score、current_fusion_score、Mask及原因、history_revision、candidate_as_of_time
微步：resource_features、变化候选行的动态特征增量、candidate_action_mask、selected_candidate_mask
动作：策略路由、epsilon、选择顺序、STOP位置
奖励：双命中差分、归一化奖励、副作用账本
状态引用：策略/基线起点快照、下一宏步引用
完整性：record_sha256
```

`split` 只允许 `train_fit`、`train_calibration`、`test`；后两者不参与梯度，其中 `train_calibration` 只是训练时间段内的固定校准子集，不是独立验证集。

环境快照必须恢复缓存及完整 LRU 顺序、通道、FIFO、在途映射、等待请求、累计账本、04 滚动状态、历史索引向量与 revision、各对象 `next_refresh_time` 和访问事件游标。允许使用“周期性完整快照 + 确定性增量”，但任意宏步都必须能够重建分层刷新集合、候选、动作、奖励和下一状态。

完整快照默认每 360 个宏步（1 小时）保存一次，其余宏步保存确定性增量。Actor 状态和自然候选基础特征每个宏步只保存一次；每个微步必须保存新的 10 维资源特征，以及所有受影响候选行的排队、完成、淘汰、访问概率等动态特征增量和两个 Mask，能够按声明的存储精度确定性重建该微步的 `[N,274]` 输入。静态向量只保存 `path_index` 并在训练时查表，当前历史向量和动态特征增量使用 `float16` 存储、训练时转为 `float32`，标量账本保留原始精度。训练抽样直接读取 Replay 中的特征，不重新调用 04。Replay 按运行分块压缩存储，单次运行使用独立输出目录。

微步 transition 规则：

```text
选择候选：r=0，gamma=1，下一状态为更新后的影子批次
选择STOP：r=宏步奖励，gamma=gamma_stop，下一状态为下一宏步
轨迹终点：gamma=0
```

6-step 只沿同一 `run_id`、同一切分的 STOP transition 累计，不得跨轨迹终点；末尾不足 6 个宏步时截断且不 bootstrap。候选微步始终使用 4.4 定义的一步目标。

### 5.2 行为策略与采样

没有可用 Critic 时先生成初始探索 Replay，每个宏步按固定种子选择：

```text
50%：simple_greedy
25%：直接 STOP
25%：随机合法候选，顺序选择至动作上限后 STOP
```

随机候选有 80% 概率从 Actor 融合分数 Top-32 中均匀选择，20% 概率从全部合法候选中均匀选择。初始 Critic 训练完成后，再生成在线双 Critic 的 epsilon-greedy Replay；epsilon 按该次训练回放的宏步位置从 `0.10` 线性降到 `0.01`，探索分支以 0.5 概率 STOP，否则从融合 Top-32 合法候选中均匀选择。

最终 Critic 训练时，初始探索 Replay 和 epsilon-greedy Replay 各占 50%。每个来源内，50% 均匀抽取宏步，50% 从非零奖励宏步抽取；按宏步实际抽样概率对 Loss 加权，使目标仍对应均匀宏步分布。非零池为空时退化为均匀抽样。

有候选动作的宏步随机取一个已执行候选 transition，并始终加入最终 STOP transition；直接 STOP 的宏步只加入 STOP。宏步内部损失先求平均，再对 batch 中宏步等权平均。

### 5.3 训练流程

```text
校验上游产物和环境配置
→ 构建并校验无预取快照
→ 运行可训练性检查
→ 生成初始探索 Replay 并训练初始 Critic
→ 生成 epsilon-greedy Replay
→ 混合两份 Replay 训练并校准最终 Critic
→ 生成优势样本并更新 Actor
→ 在训练段校准轨迹运行 05 自然召回和 06 策略评价
→ 使用新 Actor 重复上述 Replay/Critic 流程并重新校准
→ 按训练段校准结果选择并冻结策略
→ 仅在冻结后运行一次测试并生成报告
```

Actor 更新后，旧 Replay 中的查询、候选、行为分数和优势标签全部失效。旧版本只保留审计，不得继续训练新 Actor 对应的 Critic。新 `Q1`、`Q2` 的状态编码器从新 Actor 初始化，新增层使用不同随机种子重新初始化，不继承旧 Critic 权重。

首版只强化更新 Actor 一次，但包含两个 Critic 训练阶段：监督 Actor 对应的 Critic，以及强化 Actor 对应的重建 Critic。两个阶段合计最多两组参数尝试：第一组固定 `max_prefetch_per_macro_step=2` 和默认参数；第二组保持动作上限，只允许根据训练段校准结果调整一次 Critic 学习率或 `lambda_anchor`。测试结果不得触发重训或参数修改。

最终在同一训练段策略校准起点分别运行 `no_prefetch`、`simple_greedy`、`critic` 和 `actor_critic`。先排除未通过第 7 章副作用保护线的策略，再按字节命中率、读取次数命中率依次降序选择；仍相同时按 `no_prefetch`、`simple_greedy`、`critic`、`actor_critic` 的顺序优先选择更简单者。若所有主动预取策略均不通过，则冻结 `no_prefetch`。强化 Actor 未通过 4.5 自然召回保护线时，`actor_critic` 不得进入选择。

### 5.4 可训练性检查

正式训练前冻结监督 Actor，在 30 通道环境中只生成候选并执行无预取回放。至少满足：

```text
存在合法候选的宏步比例 >= 5%
训练段合法动作宏步数 >= 2,000
乐观字节收益为正的宏步数 >= 1,000
```

对合法候选 `c`，忽略未来污染和淘汰，统计其预计完成后至 `min(t+1h, 切分终点)` 之间无预取基线的 MISS 次数：

```text
optimistic_bytes(c) = total_size_bytes(c) * baseline_miss_count(c)
```

宏步内任一候选的 `optimistic_bytes > 0` 即记为乐观字节收益为正。真实未来请求只允许用于本项离线诊断，不能进入正式特征或 Replay。30 通道通过后只在该环境训练；失败时检查 60 通道上限场景；60 通道仍失败则停止 RL 训练并报告候选信号不足。10 通道只作为冻结策略的资源约束参考。

## 7. 验收

验收分为两项：

1. **能否跑通：** 完成分层索引刷新、候选生成、四种策略路由、事件回放、Replay 重建、Critic 训练、Actor 更新、检查点加载和评价。未来信息、重复任务、容量越界、非法动作和奖励对账错误均为 0；dirty、近期层和长期层分别满足 10/300/3600 秒新鲜度上限；廉价 Mask 对象的 04 候选调用数为 0；候选临时刷新前后分数可区分且不改变持久 revision。
2. **测试集效果：** 训练结束并冻结策略后，在 30 通道测试环境中一次性比较无预取、简单贪心、Critic 和 Actor-Critic，报告字节命中率、读取次数命中率、等待、额外读取、未使用预取、污染和队列指标；同时报告 10 通道冻结策略结果。若 RL 没有超过无预取或简单贪心，必须如实交付负结果和训练阶段已冻结的简单策略。

检查点和策略必须在训练段内部校准阶段按以下保护线确定：相对无预取，读取次数命中率绝对下降不超过 1 个百分点，等待请求秒增加不超过 5%，P95/P99 等待增加不超过 10%，物理读取字节增加不超过 10%，未使用预取字节占比不超过 30%。测试集复用同一口径只报告能否通过，不得用于再次选择、重训或更换策略。

本阶段对象是完整目录代理。任何结果只能说明当前代理和资源配置下是否存在方法信号，不能直接表述为文件级生产收益。
