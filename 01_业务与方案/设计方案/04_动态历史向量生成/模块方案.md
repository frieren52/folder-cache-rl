# 04 动态历史向量生成模块方案

## 1. 目标

04 使用目录近期访问记录训练动态历史编码与需求预测模型。模型供后续模块按需生成动态向量和需求预测，04 最终交付训练好的模型，不负责搭建向量库。

## 2. 历史表示

输入为 02 发布的 `path_index` 和访问时刻。时刻 `t` 的表示只能使用严格早于 `t` 的事件，并从中提取目录近期的访问频率、间隔和变化趋势。

04 只表示访问历史，不使用路径语义、目录大小、缓存、LRU、带宽或队列状态。模型推理时为目录生成动态历史向量、下一次访问时间分布及同一预测时域内的预计访问次数。

## 3. 生成过程

```text
02 访问事件
→ 构建因果训练与验证样本
→ 训练动态历史编码与需求预测模型
→ 验证模型表现
→ 导出训练好的模型
```

04 可以使用 02 发布的全量访问数据构建本模块自己的训练集和验证集，不设置测试集，也不沿用最终端到端训练与评价的时间切分。具体划分方式，以及决策步长、历史窗口、预测时域、时间分档、向量维度和训练方法在详细设计中规定。

## 4. 交付接口

| 制品位置 | 作用 |
| --- | --- |
| `outputs/runs/<run_id>/` | 保存断点检查点、逐轮损失日志和自动生成的损失曲线，不作为正式接口 |
| `outputs/releases/<model_id>/` | 保存正式模型、推理配置、特征统计、验证报告、损失日志、损失曲线和 manifest |

04 不生成或保存动态向量库。后续模块从一个明确的 `<model_id>` 发布目录加载模型，按需生成动态向量和需求预测；正式文件名和推理接口在详细设计及 04 README 中冻结。

## 5. 验收

1. 数据处理、模型训练、验证、推理和制品导出能够完整跑通。
2. 在本模块验证集上，下一次访问时间和访问次数预测达到详细设计规定的指标要求。

特征构造、模型结构、样本与标签、损失函数、训练步骤和具体评估阈值见[详细设计](详细设计.md)。
