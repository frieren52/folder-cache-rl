# 04 动态历史编码模型详细设计（初稿）

本设计说明如何训练并交付动态历史编码模型。动态向量生成和向量库构建在后续阶段完成。本文出现的参数均为首版实现值，修改后必须同步更新配置、模型制品和 manifest。

## 1. 模型输入与输出

### 1.1 输入数据

模型训练需要 02 发布的两类数据：

- `02_全局数据/artifacts/vocab/path_catalog.csv`：目录对象表，仅使用 `path_index` 校验目录身份。
- `02_全局数据/raw/access_*.txt`：目录访问事件，每行包含 `path_index` 和 `access_time`。

访问事件示例：

```text
1953 2026-06-17 23:59:02
1953 2026-06-17 23:59:02
```

04 学习的信息只有“哪个目录在什么时刻被访问”。同秒重复事件按真实次数保留；`path_index` 只用于关联对象，不进入神经网络。路径语义、目录大小、缓存、LRU、带宽、队列状态和日内时间位置均不作为首版输入。

### 1.2 输出

模型封装接口返回：

| 字段 | 类型 | 形状 | 含义 |
| --- | --- | --- | --- |
| `path_indices` | `int64` 数组 | `[B]` | 保持输入对象顺序 |
| `vectors` | `float32` 数组 | `[B, 128]` | 动态历史向量 |
| `next_access_probs` | `float32` 数组 | `[B, 10]` | 9 个首次访问时间档及“未来 1 小时无访问” |
| `expected_access_counts` | `float32` 数组 | `[B]` | 未来 1 小时预计访问次数 |

动态历史向量是两个预测任务共享的表示，不是独立预测任务。三个输出分别表示当前访问模式、下一次访问时间和未来访问强度。

正式输出必须保持输入顺序，全部为有限值；动态向量逐行 L2 归一化，时间分布每行和为 1，预计访问次数非负。

## 2. 模型结构

### 2.1 总体结构

首版采用四路 TCN、跨尺度 Transformer、状态编码器和两个预测头：

```text
最近 60 秒序列 ─→ TCN ─┐
最近 5 分钟序列 → TCN ─┤
最近 1 小时序列 → TCN ─┼→ 加入尺度与位置编码 → Transformer → 128 维时间表示 ─┐
最近 24 小时序列 → TCN ┘                                                    ├→ 融合层 → 128 维动态表示
4 维基础状态 → 状态编码器 → 64 维状态表示 ───────────────────────────────────┘             ├→ L2 归一化向量
                                                                                           ├→ 首次访问时间头
                                                                                           └→ 访问次数头
```

四路序列的依据是：不同访问秒间隔中约 88.14% 不超过 30 秒，因此增加一秒粒度分支；相邻日活跃对象仍存在约 30.03% 的 Jaccard 和 45.10% 的前日对象保留率，因此保留 24 小时分支。

按本节首版参数估算，模型约有 172 万个可训练参数。`train.py` 必须在启动时计算实际可训练参数量，并写入训练日志、`evaluation_report.json` 和 `manifest.json`。

### 2.2 网络输入张量

数据构造器向模型提供：

| 张量 | 类型 | 形状 | 内容 |
| --- | --- | --- | --- |
| `second_counts` | `float32` | `[B, 60, 1]` | 最近 60 秒，每秒访问次数的 `log1p` |
| `short_counts` | `float32` | `[B, 60, 1]` | 最近 5 分钟，每 5 秒访问次数的 `log1p` |
| `medium_counts` | `float32` | `[B, 60, 1]` | 最近 1 小时，每分钟访问次数的 `log1p` |
| `long_counts` | `float32` | `[B, 96, 1]` | 最近 24 小时，每 15 分钟访问次数的 `log1p` |
| `history_state` | `float32` | `[B, 4]` | 两个标准化连续特征和两个缺失标记 |

所有序列按从最早时间桶到最新时间桶排列，内存布局为 batch-first。模型前向接口固定为：

```python
forward(
    second_counts,
    short_counts,
    medium_counts,
    long_counts,
    history_state,
)
```

### 2.3 四路 TCN

四路 TCN 结构相同、参数互不共享。每路输入先从 `[B, N, 1]` 转置为 `[B, 1, N]`，然后执行：

```text
Conv1d(1, 128, kernel_size=1)
→ 残差块(dilation=1)
→ 残差块(dilation=2)
→ 残差块(dilation=4)
→ 转置为 [B, N, 128]
```

每个残差块定义为：

```text
输入 x
→ 左侧补零 2 × dilation
→ Conv1d(128, 128, kernel_size=3, dilation=dilation, padding=0)
→ GELU
→ Dropout(0.1)
→ Conv1d(128, 128, kernel_size=1)
→ Dropout(0.1)
→ 与 x 相加
→ LayerNorm(128)
```

残差相加后先将张量转为 `[B, N, 128]` 执行 LayerNorm，再转回 `[B, 128, N]` 进入下一残差块。仅在左侧补零，保证每个位置不读取其右侧时间桶。最后一个残差块结束后输出 `[B, N, 128]`。

### 2.4 Token 拼接与编码

四路 TCN 输出按以下顺序拼接：

```text
[CLS]
最近 60 秒的 60 个 Token
最近 5 分钟的 60 个 Token
最近 1 小时的 60 个 Token
最近 24 小时的 96 个 Token
```

总长度为 `1 + 60 + 60 + 60 + 96 = 277`。每个历史 Token 加上：

- 对应分支的可学习尺度编码，形状为 `[4, 128]`；
- 分支内部的可学习位置编码，四个分支分别为 `[60,128]`、`[60,128]`、`[60,128]` 和 `[96,128]`。

`[CLS]` 使用独立可学习向量，不加入尺度编码。所有可学习 Token 和位置编码使用截断正态分布初始化，标准差为 `0.02`。

### 2.5 跨尺度 Transformer

拼接后的 277 个 Token 输入 PyTorch `TransformerEncoder`：

| 参数 | 首版值 |
| --- | ---: |
| `d_model` | 128 |
| `nhead` | 4 |
| `num_layers` | 4 |
| `dim_feedforward` | 512 |
| `dropout` | 0.1 |
| `activation` | GELU |
| `batch_first` | `true` |
| `norm_first` | `true` |

历史 Token 均早于快照时刻，Transformer 内部不使用因果注意力掩码。编码器末尾增加 `LayerNorm(128)`，取 `[CLS]` 输出作为 128 维时间表示。

### 2.6 状态编码器

`history_state` 的四个元素依次为：

1. 标准化后的 `log1p(距上次访问秒数)`；
2. 标准化后的 `log1p(最近两个不同访问秒的间隔)`；
3. 无历史标记；
4. 无有效访问间隔标记。

样本从完整一天预热结束后开始生成，因此每条样本都具有完整的 24 小时可观测范围，不再输入恒为 1 的历史覆盖率。

状态编码器为：

```text
Linear(4, 64, bias=True)
→ GELU
→ Dropout(0.1)
→ Linear(64, 64, bias=True)
→ LayerNorm(64)
```

### 2.7 融合层

```text
128 维时间表示 + 64 维状态表示
→ Concatenate(192)
→ LayerNorm(192)
→ Linear(192, 256, bias=True)
→ GELU
→ Dropout(0.1)
→ Linear(256, 128, bias=True)
→ 128 维未归一化动态表示 h
```

正式动态向量为：

```text
z = L2Normalize(h, dim=-1, eps=1e-12)
```

预测头使用未归一化表示 `h`，避免 L2 归一化限制预测幅度。

### 2.8 首次访问时间头

时间头由两个线性层组成：

```text
access_logit = Linear(128, 1)(h)
time_logits = Linear(128, 9)(h)
```

推理时组合为 10 档概率：

```text
p_access = sigmoid(access_logit)
q_time = softmax(time_logits)
next_access_probs[0:9] = p_access × q_time
next_access_probs[9] = 1 - p_access
```

### 2.9 访问次数头

```text
h
→ Linear(128, 64, bias=True)
→ GELU
→ Dropout(0.1)
→ Linear(64, 1, bias=True)
→ Softplus
→ predicted_log_count
```

正式预计次数为：

```text
expected_access_counts = expm1(predicted_log_count)
```

## 3. 训练目标

### 3.1 是否访问损失

设未来 1 小时是否访问的标签为 `y_access`：

```text
L_access = BCEWithLogits(access_logit, y_access)
```

该损失在全部样本上计算，不设置类别权重。

### 3.2 条件时间损失

未来 1 小时内发生访问时，设首次访问时间档为 `y_time`：

```text
L_time = CrossEntropy(time_logits, y_time)
```

`L_time` 只对 `y_access=1` 的样本计算；批次中没有正样本时取 0。

### 3.3 次数损失

设未来 1 小时真实访问次数为 `y_count`：

```text
L_count = Huber(predicted_log_count, log1p(y_count), delta=1.0)
```

次数标签保留同秒重复访问，用于区分一次访问和短时间内多次访问。

首版保留 Huber 回归，不引入泊松或负二项分布。`expected_access_counts` 在本设计中表示 `predicted_log_count` 经 `expm1` 反变换得到的次数点估计，不将其解释为严格的概率分布期望。

### 3.4 总损失

```text
L_total = 1.0 × L_access + 1.0 × L_time + 1.0 × L_count
```

三项损失先分别对有效样本求平均，再按权重相加。第一版不增加排序、对比学习或短期辅助任务。

## 4. 样本构造与切分

### 4.1 数据切分

04 使用 02 的全量事件构造历史，但只从完整一天预热结束后的 `2026-06-19 00:00:00` 开始生成样本。训练集和验证集按时间先后以 `4:1` 划分，不设置测试集，也不沿用最终端到端训练与评价的固定日期切分。

定义 `sample_start=2026-06-19 00:00:00`，`log_end_exclusive` 为最晚事件时刻加 1 秒。先枚举全部候选快照：

```text
S = {t | t 从 sample_start 起每 10 秒取值，且 t + 3600 秒 <= log_end_exclusive}
```

`split_time` 必须是 10 秒整点。对每个可行的 `split_time`，定义：

```text
train_snapshots = {t ∈ S | t + 3600 秒 <= split_time}
validation_snapshots = {t ∈ S | t >= split_time}
```

选择使 `len(train_snapshots) / (len(train_snapshots) + len(validation_snapshots))` 最接近 `0.8` 的 `split_time`；差值相同时选择更早的时刻。`(split_time-3600 秒, split_time)` 内的快照作为隔离区，不生成样本。这样 `4:1` 按最终可生成的训练与验证快照数量计算，同时保证训练标签不进入验证期。

验证历史可以使用 `split_time` 之前已经发生的事件。`prepare_data.py` 必须把最终 `sample_start`、`split_time`、隔离区边界以及训练和验证快照数写入 `data_meta.json`。

切分结果随1小时标签时域重新计算；程序必须将候选、训练、验证和隔离快照数写入`data_meta.json`，不得复用30分钟时域生成的数据元信息。

所有目录都可以在两个时间段出现。该切分验证模型能否使用较早时期学到的访问模式预测后续时期的访问。

### 4.2 快照与对象采样

首个快照固定为 `2026-06-19 00:00:00`，后续每 10 秒推进。该 10 秒只是训练样本的快照间隔，不限制后续系统的实际决策周期。

每个快照先统计全部目录在 `[t-86400 秒, t)` 内的不同访问秒数和事件总数。无历史目录和单次历史目录直接成池；其余目录按 24 小时事件总数从小到大排序，使用 `(event_count_24h, path_index)` 保证并列时顺序稳定，再按对象数量分位点划分低频、中频和高频池：

设排序后共有 `M` 个目录，`cut50=floor(0.5×M)`、`cut90=floor(0.9×M)`：索引 `[0,cut50)` 为低频池，`[cut50,cut90)` 为中频池，`[cut90,M)` 为高频池。

| 样本池 | 历史条件 | 每快照数量 | 占比 |
| --- | --- | ---: | ---: |
| 高频历史目录 | 至少 2 个不同访问秒，事件总数位于对象数 P90 以上 | 12 | 30% |
| 中频历史目录 | 至少 2 个不同访问秒，事件总数位于对象数 P50～P90 | 12 | 30% |
| 低频历史目录 | 至少 2 个不同访问秒，事件总数位于对象数 P50 以下 | 8 | 20% |
| 单次历史目录 | 恰好 1 个不同访问秒 | 4 | 10% |
| 无历史目录 | 0 个访问秒 | 4 | 10% |

五个池内分别按 `path_index` 均匀、无放回抽样。某个池不足目标数量时全部保留，不从其他池补足，因此单个快照最多产生 40 条样本。从 6 月 19 日零点开始并排除切分隔离区后，首版最多生成 2059240 条样本，其中训练集最多 1647400 条、验证集最多 411840 条；实际数量以候选池缺额后的构造报告为准。

高、中、低频历史池让模型同时学习不同访问强度，并提高高频目录在训练样本中的占比；单次历史目录用于学习只有新近程度、没有访问间隔时的表示；无历史目录用于保证全部目录都能获得定义明确的动态向量。无历史目录没有可区分的动态信息，因此它们的动态向量可以相同，目录差异由静态语义向量提供。

抽样前将各池的 `path_index` 升序排列，再使用 `numpy.random.Generator(PCG64(2026 + snapshot_unix_seconds))` 抽样。不得根据未来是否访问、首次访问时间或访问次数筛选或补齐样本。

验证样本准备完成后固定保存，训练期间不得重新抽取。

#### 构造实现约束

样本构造按事件时间执行单向扫描，不得在每个快照重新遍历原始日志或重新排序全部目录：

1. 为每个目录维护最近 24 小时事件的双端队列、事件总数和不同访问秒数。推进到快照 `t` 时，只加入时间 `<t` 的新事件，并移除时间 `<t-86400` 的旧事件。
2. 分别维护无历史、单次历史和多次历史目录的有序秩索引。前两类按 `path_index` 排序；多次历史目录按 `(event_count_24h, path_index)` 排序。索引必须支持受影响目录的增删、对象总数和按秩取第 `k` 个对象，不允许每 10 秒全量重排。
3. P50/P90 直接由多次历史索引的对象秩确定。池内均匀抽样先由固定随机数生成器抽取不重复的秩，再从索引取得目录，结果必须与“完整排序后按秩抽样”的参考实现一致。
4. 只为当次抽中的目录构造四路时间桶。完整事件流另建只读的逐目录时间索引；目录抽中之后才能用二分查找构造未来标签，候选分层和抽样过程不得查询该索引的未来区间。

测试使用小规模事件集同时运行滚动实现和全量参考实现，逐快照比较池划分、抽样结果、四路特征和标签，任一差异均视为错误。

### 4.3 时间桶构造

对快照时刻 `t`，一个范围为 `W`、桶宽为 `w`、桶数为 `N=W/w` 的序列，第 `j` 个桶定义为：

```text
[t - W + j × w, t - W + (j + 1) × w)，j = 0, ..., N-1
```

四路参数为：

| 字段 | `W` | `w` | `N` |
| --- | ---: | ---: | ---: |
| `second_counts` | 60 秒 | 1 秒 | 60 |
| `short_counts` | 300 秒 | 5 秒 | 60 |
| `medium_counts` | 3600 秒 | 60 秒 | 60 |
| `long_counts` | 86400 秒 | 900 秒 | 96 |

每个事件分别计入四个尺度中覆盖它的时间桶；同秒重复事件累加。桶计数完成后执行 `log1p` 并转换为 `float32`。

### 4.4 基础状态构造

两个连续特征按以下规则生成：

- 有历史时，距上次访问秒数为 `t` 与最后事件时刻之差；无历史时取 86400，并设置无历史标记为 1。
- 至少存在两个不同访问秒时，最近访问间隔为最后两个不同访问秒之差；否则取 86400，并设置无有效间隔标记为 1。
- 两个时间值均截断到 `[0, 86400]` 后执行 `log1p`。

两个连续特征只使用训练样本统计量标准化，数据构造固定执行两遍：

1. 第一遍将未标准化样本写入本次数据运行的 staging 目录，同时用 `float64` Welford 算法累计训练集两个连续特征的均值和总体方差。
2. 总体标准差按 `sqrt(M2/N)` 计算，即 `ddof=0`；标准差小于 `1e-6` 时实际除数取 1。
3. 第二遍顺序读取 staging 分片，只标准化前两个连续值，再写入正式训练和验证分片；两个缺失标记保持 0/1 不变。验证集和推理固定复用训练集统计量。

`feature_stats.json` 按 `history_state` 顺序记录特征名、训练样本数、均值、原始标准差和实际使用标准差。正式数据完整性检查通过后才能发布数据集；staging 内容不属于正式接口。

### 4.5 预测标签

预测时域固定为 `[t, t+3600 秒)`。首次访问使用 9 个前闭后开时间档：

| 类别 | 起点（秒） | 终点（秒） |
| ---: | ---: | ---: |
| 0 | 0 | 5 |
| 1 | 5 | 10 |
| 2 | 10 | 30 |
| 3 | 30 | 60 |
| 4 | 60 | 120 |
| 5 | 120 | 300 |
| 6 | 300 | 600 |
| 7 | 600 | 1800 |
| 8 | 1800 | 3600 |

区间内至少存在一次访问时，`y_access=1`，`y_time` 为首次访问所在类别；没有访问时，`y_access=0`、`y_time=-1`。`y_count` 为区间内全部访问事件数，包括同秒重复事件。

数据末尾无法完整观察 3600 秒标签时域的快照不生成样本。

### 4.6 样本文件字段

训练集和验证集的全部 Parquet 分片使用相同字段：

| 字段 | 类型 |
| --- | --- |
| `path_index` | `int64` |
| `snapshot_time` | `timestamp[ms, tz=Asia/Shanghai]`，值必须对齐到整秒 |
| `history_tier` | `int8`，0=无历史、1=单次、2=低频、3=中频、4=高频 |
| `second_counts` | `fixed_size_list<float32>[60]` |
| `short_counts` | `fixed_size_list<float32>[60]` |
| `medium_counts` | `fixed_size_list<float32>[60]` |
| `long_counts` | `fixed_size_list<float32>[96]` |
| `history_state` | `fixed_size_list<float32>[4]` |
| `y_access` | `int8` |
| `y_time` | `int8`，无访问时为 `-1` |
| `y_count` | `int32` |

全部字段均为 non-nullable。`snapshot_time` 的 Parquet 物理值为 UTC Unix 毫秒，且必须能被 1000 整除；Arrow schema 保留 `Asia/Shanghai` 时区元数据，读取后不得按宿主机本地时区解释。禁止使用 INT96 时间戳，也禁止将定长数组退化为可空的变长 List。

### 4.7 原始事件预处理

按文件名顺序读取 `access_*.txt`。每行格式固定为：

```text
<path_index> <YYYY-MM-DD> <HH:MM:SS>
```

- `path_catalog.csv` 必须包含 non-null、唯一的 `int64 path_index`；编号不要求连续，重复编号立即报错。构造时记录目录行数和文件 SHA-256。
- 事件中的 `path_index` 按 `int64` 解析，且必须存在于 `path_catalog.csv`。
- 访问时间按 `Asia/Shanghai` 时区解释，精度为秒。
- 同一目录在同一秒内的重复事件全部保留，不去重、不聚合。
- 每个文件内部以及相邻文件之间的事件时间必须非递减。
- 字段格式错误、非法时间、未知 `path_index` 或乱序事件均立即终止构造并报告文件名与行号，不得静默跳过。

构造程序记录每个输入文件的行数、首末事件时间和 SHA-256。全部输入文件的总行数必须等于成功解析的事件数；这些摘要写入 `data_meta.json` 和数据集目录内的 `manifest.json`。

### 4.8 样本存储与加载

训练集和验证集分别保存为分片目录：

```text
data/
├── staging/<dataset_id>/
└── datasets/<dataset_id>/
    ├── train/
    │   ├── part-00000.parquet
    │   └── ...
    └── validation/
        ├── part-00000.parquet
        └── ...
```

- `dataset_id` 由命令行显式传入，只允许字母、数字、点、下划线和短横线。目标 staging 或正式目录已存在时立即报错，不得覆盖；通过全部完整性检查后才将 staging 结果原子发布到 `datasets/<dataset_id>/`。
- 每个分片最多保存 100000 条样本，每个 Parquet Row Group 最多保存 10000 条样本。
- Parquet 版本固定为 2.6，使用 ZSTD level 3 压缩，不启用 INT96 时间戳；四路时间序列和基础状态使用定长 `float32` 数组。
- 分片内按 `(snapshot_time, path_index)` 升序排列，分片编号按时间顺序连续生成。
- 四路特征、基础状态和标签均由 `prepare_data.py` 提前生成；训练期间不重新扫描原始事件或在线构造特征。
- 训练集每轮恰好遍历一次。加载器使用 `seed + epoch` 依次确定性打乱分片、Row Group 和 Row Group 内样本，不进行有放回抽样。
- 每个 worker 读取完整 Row Group 后，直接按微批量切片并一次性转换为连续 Tensor；禁止逐样本复制数组、逐样本创建 Tensor 后再拼批。
- 验证集按分片编号和行顺序固定读取，不打乱。
- 多进程或多卡训练时，以完整 Row Group 为最小单位分配给不同 worker 和 rank，同一轮内不得重复或遗漏样本。
- 末尾不足一个微批次的样本仍参与训练和验证，不设置 `drop_last`。

按最多约 206 万条样本估算，训练集最多约 17 个分片，验证集最多约 5 个分片。`data_meta.json` 记录 `dataset_id`、每个分片的相对路径、数据集归属、样本数、首末快照时间、Row Group 数和 SHA-256。

### 4.9 数据构造报告

`prepare_data.py` 在样本生成完成后同时输出供程序读取的 `data_report.json` 和供人工审阅的 `data_report.md`。两份报告的数据来源相同，至少包含：

1. **数据与切分：** 原始事件数、目录数、时间范围、`split_time`，以及训练集和验证集各自的快照数、样本数、覆盖目录数、分片数和每快照实际样本数分布。
2. **条件采样：** 五个历史层级各自的目标数量、实际数量和占比，以及候选池不足造成的缺额快照数；训练集和验证集分别统计。
3. **输入稀疏性：** 四路输入各自的全零样本率、非零桶数量的均值及 P50/P90/P95/P99、尾部连续零桶数量分布；以上指标同时按数据集和 `history_tier` 分组统计。
4. **标签分布：** 未来 1 小时访问率、九个首次访问时间桶的数量与占比，以及访问次数的均值、P50/P90/P95/P99和最大值；训练集和验证集分别统计。
5. **状态特征：** 两个连续状态特征在标准化前的均值、标准差和截断比例，以及无历史标记、无有效访问间隔标记的占比。
6. **完整性检查：** 非有限值数量、定长字段长度错误数量、输入总行数与解析事件数是否相等、样本和分片汇总数量是否相等。

只要完整性检查存在错误，`prepare_data.py` 就必须返回非零退出码，不得发布部分成功的数据集。四路输入稀疏性只作为模型结构复审依据，首版不在数据构造阶段设置通过门槛。

## 5. 训练过程

```text
读取目录对象表和全量访问事件
→ 完成一天预热并枚举可用快照
→ 按快照数量确定时间切分和隔离区
→ 滚动构造未标准化样本及训练集特征统计量
→ 标准化状态特征并发布固定训练、验证分片
→ 训练动态历史编码模型
→ 每轮在验证集评估并选择最佳模型
→ 使用最佳模型生成验证报告
→ 导出带完整推理依赖的正式模型制品
```

### 5.1 训练参数

| 参数 | 首版值 |
| --- | ---: |
| 优化器 | AdamW |
| 学习率 | `1e-4` |
| Adam betas | `(0.9, 0.999)` |
| Adam epsilon | `1e-8` |
| 权重衰减 | `1e-4` |
| 微批量大小 | 1024 |
| 梯度累积步数 | 1 |
| 有效批量大小 | 1024 |
| 梯度裁剪 | L2 范数 1.0 |
| 最大轮数 | 30 |
| 提前停止 | 连续 5 轮无改善 |
| 最小改善量 | `1e-4` |
| 随机种子 | 2026 |
| 数据加载 worker | 4 |
| 批次进度输出 | 每20个微批次或最长60秒 |
| 分布式训练 | 首版关闭 |
| 设备与精度 | 自动解析并记录 |

首版单进程有效批量大小为 `micro_batch_size × gradient_accumulation_steps = 1024`；以后启用多进程时再乘 `world_size`，不得仍记录为1024。学习率前5%更新步数线性预热，之后使用余弦衰减到`1e-6`。末尾不足一个完整微批次的样本仍完成一次参数更新。

`device=auto` 时优先使用 CUDA，否则使用 CPU；`precision=auto` 时，仅在 CUDA 设备明确支持 BF16 时使用 BF16，其余情况使用 FP32。训练启动后不得因显存不足自动缩小微批量；需要调整时必须生成新配置和新 `run_id`。实际设备、精度、批量和 worker 数写入运行日志及 manifest。

### 5.2 检查点选择

每轮计算验证集 `L_total`，按其最小值保存最佳模型；连续 5 轮改善不足 `1e-4` 时提前停止。训练结束后重新加载最佳模型，在固定验证样本上生成正式验证报告。

每次训练写入唯一的 `outputs/runs/<run_id>/`，至少包含`resolved_config.yaml`、`training_progress.jsonl`、`live_training_metrics.png`、`loss_history.jsonl`、`loss_curves.png`、`run_meta.json`和`checkpoints/{last.pt,best.pt}`。未指定`--resume`时，如果`run_id`已存在必须报错，禁止覆盖。

断点检查点保存模型参数、优化器状态、学习率调度器状态、梯度缩放器状态（启用时）、当前轮数、全局更新步、随机数状态、`dataset_id`、数据 manifest SHA-256 和完整训练配置。`--resume` 只能恢复同一 `run_id`，且数据摘要和模型、损失、批量配置必须完全一致，否则终止运行。

### 5.3 损失日志与曲线

训练和验证每20个微批次或最长60秒向控制台输出一次实时进度。每条记录至少包含当前/总batch、完成比例、已处理/总样本、累计耗时、预计剩余秒数、全轮和区间吞吐量、区间与全轮累计四项loss、学习率及CUDA可用时的已分配/保留显存。

同一记录立即追加到`training_progress.jsonl`；训练阶段每次记录后原子重绘`live_training_metrics.png`，展示区间/累计四项loss、吞吐量和GPU显存。每轮完成后另向`loss_history.jsonl`追加训练/验证汇总，并重绘`loss_curves.png`。实时图仅是训练观测制品，不改变损失计算、梯度或模型接口；训练中断后已经落盘的进度仍保留。

### 6.5 模型加载

```python
encoder = DynamicHistoryEncoder.load(
    "04_动态历史向量生成/outputs/releases/<model_id>",
    device="auto",
)
result = encoder.encode(history_records)
```

`load` 先校验 manifest 中全部发布文件 SHA-256、配置 schema 版本和模型参数形状，任一不一致均拒绝加载。

`history_records` 中每条记录包含 `path_index:int64`、带 `Asia/Shanghai` 时区且精确到秒的 `snapshot_time`，以及覆盖 `[snapshot_time-24 小时,snapshot_time)` 的非递减 `access_times`。同秒重复允许保留；出现等于或晚于快照的事件、非法时间、非有限编号或乱序时立即报错。早于 24 小时窗口的事件可以忽略。调用方负责保证这 24 小时事件范围已经完整观测，空列表表示完整观察后确实无访问。

推理快照只要求对齐到秒，不要求对齐训练使用的 10 秒网格。`encode` 内部使用发布目录中的 `feature_stats.json` 和训练完全相同的特征构造，保持输入顺序并返回 `path_indices`、动态历史向量、首次访问时间分布和预计访问次数。

后续阶段使用该接口按需生成动态向量并构建向量库，04 不生成向量文件。

### 7.2 模型指标

验证集至少报告：

- 10 档首次访问时间分布的多分类 Brier 分数和负对数似然；
- 未来 1 小时访问次数的 MAE；
- 三项指标相对简单历史频率基线的变化。

设真实 10 档类别的 one-hot 向量为 `y`，各指标按以下方式计算：

```text
Brier = mean(sum((next_access_probs - y)², axis=1))
NLL = mean(-log(clip(next_access_probs[真实类别], 1e-12, 1)))
Count MAE = mean(abs(expected_access_counts - y_count))
```

历史频率基线使用最近 1 小时事件数估计每秒访问率 `λ`：

```text
λ = 最近 1 小时访问次数 / 3600
P(首次访问位于 [a,b)) = exp(-λa) - exp(-λb)
P(未来 1 小时无访问) = exp(-λ × 3600)
预计访问次数 = λ × 3600
```

首轮暂定门槛为：模型 Brier 分数和次数 MAE 均至少比基线降低 5%，负对数似然不得高于基线。配置中的 `thresholds_provisional=true` 表示这些数值只用于第一次全量验证观察，尚不是冻结业务门槛；评估脚本输出 `provisional_pass`，不得表述为最终验收结论。第一次全量验证后再根据模型与基线的实际差距确认或调整门槛，冻结时必须形成新配置和新 `model_id`。
