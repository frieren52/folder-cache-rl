# 业务与方案

本目录只保留当前有效的业务口径和可实施方案，不再保存讨论稿、备选稿或废弃架构。内容按“先约束、后方案”的顺序组织；若文档与代码不一致，应先确认差异属于已实现状态还是待实施目标，再同步修正文档或代码，不能静默选择其中一份。

## 阅读顺序

1. 先读[业务约束](业务约束.md)，确认目录对象、完整目录动作、3% 容量、固定 LRU、业务目标和适用边界。
2. 再读[总体方案](设计方案/00_总体架构/总体方案.md)，理解 02—07 的职责和接口。
3. 实施某个模块时，只进入与工程同名的方案目录，并以该模块的配置、README 和测试核对细节。

## 维护规则

- **只留现行方案。** 新决策生效后直接修改对应模块方案；需要追溯时依赖版本控制，不在目录内复制“方案一”“最终版”“讨论记录”。
- **事实与计划分开。** 文档必须显式标注“已实现”“数据已就绪”或“待实施”，不得把计划产物写成已经存在。
- **接口必须可核验。** 跨模块制品要绑定版本、维度、对象映射和 SHA256；不一致时停止运行。
- **字段遵循上游。** 文档中的中文名称用于解释，代码和数据继续使用已经存在的原始键名。
- **报告不是训练接口。** `02_全局数据/processed/reports/` 只用于阅读和审计，下游只读取版本化制品。
