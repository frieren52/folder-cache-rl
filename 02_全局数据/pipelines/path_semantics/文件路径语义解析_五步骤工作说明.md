# 文件路径语义解析：五步骤工作说明

## 1. 项目目标与数据边界

本流程的目标是把原始目录路径转换为可解释、可审计、适合后续Embedding和文件预取模型使用的结构化语义。

原始输入为：

- `recovered_attachments_merged/合并完整数据.txt`
- `recovered_attachments_merged/路径与文件名解析规则.md`
- `recovered_attachments_merged/卫星命名规则.md`

其中`合并完整数据.txt`每行格式为：

```text
访问次数 目录路径 聚合数据大小
```

需要特别说明：当前49,922条记录是目录级聚合路径，不包含目录内部的具体文件名。因此本流程能够区分目录、产品、日期目录、卫星、仪器和等级等信息，但不能区分同一目录下的多个具体文件。

总体流程为：

```text
原始目录聚合数据
  → 步骤1：路径与规则审计
  → 步骤2：Token候选类型识别
  → 步骤3：分支路由与状态机解析
  → 步骤4：高价值分支扩展与复核
  → 步骤5：生成Embedding输入和语义去重目录
```

## 2. 步骤1：路径与既有规则审计

### 2.1 输入

- `合并完整数据.txt`
- AI生成的`路径与文件名解析规则.md`
- 辅助参考`卫星命名规则.md`

AI生成规则只作为候选假设，没有直接当成业务真值。

### 2.2 完成的工作

1. 解析全部输入行，检查字段数量、路径格式、访问次数和数据大小是否合法。
2. 将路径按`/`拆成层级Token。
3. 对日期、年份、分辨率、卫星代码等具有稳定外形的Token进行归一化占位。
4. 统计路径深度、根目录、前三层分支、每层高频Token和归一化路径骨架。
5. 将真实数据统计与已有规则逐项对比，检查“固定第N层代表固定语义”的假设是否成立。

### 2.3 关键结果

- 有效记录：49,922条。
- 异常记录：0条。
- 总访问次数：30,549,077次。
- 聚合数据大小：259,724,165,681,928字节。
- 归一化路径骨架：1,711种。
- Top 100骨架覆盖72.1766%。
- Top 500骨架覆盖88.4520%。
- Top 1,000骨架覆盖97.1476%。
- 输入中具体文件名记录：0条。

审计证明，不同根目录和子系统的层级语法不同，不能使用一套全局固定槽位。例如OUTSHARE主分支的卫星、仪器和等级位置比较稳定，而DSSCACHE下存在处理目录、外部卫星、模拟数据和产品族等多种结构。

### 2.4 输出

归档目录：`processed/reports/path_semantics/01_audit/`

## 3. 步骤2：Token候选类型识别

### 3.1 输入

- 原始49,922条目录路径。
- 步骤1得到的路径骨架和层级统计。
- 已有规则中能够被真实数据验证的代码表。

### 3.2 完成的工作

为路径中的每一次Token出现生成候选语义类型，而不是简单建立“Token到唯一类别”的全局字典。

识别依据包括：

1. 强正则：日期、年份、分辨率、经纬度、数值编号等。
2. 已验证代码表：卫星、仪器、数据等级、区域类型、聚合周期、投影和格式。
3. 路径上下文：根目录、所处分支、Token深度、前后相邻Token。
4. 候选竞争：同一Token可能产生多个类型候选，并保留置信度、证据和歧义标志。

没有匹配规则的Token保留为`unknown`，没有为了提高覆盖率而强行猜测中文业务含义。

### 3.3 关键结果

- Token出现次数：485,857次。
- 唯一Token：3,375个。
- 中高置信Token覆盖：99.4247%。
- 未知Token出现：2,405次，占0.4950%。
- 歧义Token出现：1,197次，占0.2464%。
- 未知唯一Token：135个。
- 多义或上下文依赖唯一Token：28个。
- 代表Token自测：通过。

99.4247%表示Token外形和上下文能够产生中高置信候选，不代表所有业务缩写都已经获得准确中文释义。

### 3.4 输出

归档目录：`processed/reports/path_semantics/02_token_classification/`

- `步骤2_Token类型识别报告.md`：分类规则与统计说明。
- `token_catalog.csv`：唯一Token及候选类型目录。
- `token_occurrences.csv.gz`：每次Token出现的分类结果。
- `unknown_tokens.csv`：未知Token清单。
- `ambiguous_tokens.csv`：歧义Token清单。
- `field_type_coverage.csv`：字段类型覆盖率。
- `step2_summary.json`：总体统计。

实现脚本：`path_semantics/02_classify_path_tokens.py`。

## 4. 步骤3：分支路由与状态机语义解析

### 4.1 输入

- 原始目录路径。
- 步骤2的Token分类逻辑和候选证据。
- 步骤1识别出的主流路径骨架。

### 4.2 完成的工作

建立“先按路径前缀路由，再在分支内部按状态解析”的解析器。第一版专用路由包括：

1. `FYDATAOUTSHARE/DATAIOT/FY3`
2. `FYDATAOUTSHARE/DATA/FY3`
3. `FYDATAARCH/DSSCACHE/FY3F、FY3G、FY3H`
4. `FYDATAINSHARE/BAKIOT/FY3`

状态机完成以下处理：

- 识别根目录、子系统、数据域、卫星、仪器、等级和产品。
- 在等级之后按Token类型解析产品、区域、周期、投影、分辨率、方向、年份和日期。
- 允许DSSCACHE路径中出现`TEMPWORK`、`MIPS`、`ENGIN`等处理阶段。
- 防止把处理目录后的投影或格式误判成仪器。
- 解析`ASCEND_6250M`等复合Token。
- 将第二个等级保存在`data_sublevel`，不覆盖主等级。
- 同时保存规范值、原始值、来源深度、置信度和证据。
- 未确认Token进入`extra_tokens`；竞争字段进入`field_conflicts`。

未建立专用语法的路径使用保守fallback解析器。

### 4.3 关键结果

- 专用路由覆盖：48,126条，占96.4024%。
- 完整解析：47,867条。
- 专用路径带未解释Token：259条。
- fallback：1,796条。
- 专用路由字段冲突：0条。
- Python语法检查和代表路径自测：通过。

### 4.4 输出

归档目录：`processed/reports/path_semantics/03_parser_baseline/`

- `步骤3_路径状态机解析报告.md`：解析器设计和结果。
- `parsed_paths.csv.gz`：全部路径结构化结果。
- `parsed_path_samples.jsonl`：带证据、置信度和告警的样例。
- `route_summary.csv`：路由规模和解析状态。
- `field_coverage_by_route.csv`：各路由字段覆盖率。
- `field_value_catalog.csv`：字段值频次和示例。

## 5. 步骤4：高价值分支扩展与复核

### 5.1 输入

- 步骤3的1,796条fallback路径。
- `path_shape_summary.csv`中的真实骨架。
- `unresolved_extra_tokens.csv`中的高频附加Token。

### 5.2 完成的工作

首先按访问规模和结构稳定程度检查fallback分支，只为能够从路径上下文确认字段角色的分支建立专用规则。新增支持包括：

- FY4B、JPSS1、METOPC直接平台分支。
- FYSIMU模拟卫星和模拟仪器分支。
- EXTSAT外部数据分支，并区分SATE与NAFP。
- RS、DQ、GF5A分支。
- DSSCACHE下FY3D/E、FY3模拟数据和`TEMPWORK/FY3平台`变体。

同时扩展安全复合Token：

- `4KM`等一位KM分辨率。
- `5DAY`、`00HOUR`、`12HOUR`。
- `DAILY_5000M`。
- `ASCENDKu`、`DESCENDKu`。
- 短数字实例候选。
- `01MVk`、`05MVk`、`WRADC`、`OBC`等产品变体候选。

对于`SPAC`、`MOS`、`RNE`等无法仅凭路径确认角色的业务缩写，继续保留原Token，不输出未经验证的中文含义。

### 5.3 关键结果

- 专用路由覆盖：48,126 → 49,706条。
- 覆盖率：96.4024% → 99.5673%。
- 新增覆盖：1,580条。
- fallback：1,796 → 216条。
- 专用路径带未解释Token：259 → 88条。
- 专用路由字段冲突：0条。
- 新增专用路由：11个。
- 语法检查和代表路径自测：通过。

剩余216条主要属于Python软件库、日志、质控工作目录、交换区和临时目录。它们不适合强行套用卫星产品字段，因此继续保留fallback状态。

## 6. 步骤5：生成Embedding输入与语义去重目录

### 6.1 输入

- 步骤4的`parsed_paths.csv.gz`。
- 每条路径的规范字段、原始值、置信度、证据、未解释Token和解析质量。
- 原始访问次数、聚合数据大小和观测日期。

### 6.2 完成的工作

1. 按固定字段顺序生成带中文角色标签的`embedding_text`。
2. 生成机器可读的`semantic_sequence`，例如：

   ```text
   [DOMAIN=FY3][SATELLITE=FY3F][INSTRUMENT=GNOS][LEVEL=L1][PRODUCT=IEG]
   ```

3. 生成`semantic_text_strict`，只保留置信度不低于0.70的解释字段。
4. 将未确认Token以“原始业务标记”保留在推荐文本中，但不虚构含义。
5. 将观测年份、观测日期和实例编号分离到`instance_context`。
6. 将存储根目录、子系统和解析路由分离到`source_context`。
7. 将访问次数和数据大小保留为旁路数值特征，不拼入静态语义文本。
8. 按`semantic_sequence`生成稳定的`semantic_group_id`，使不同日期但语义相同的路径共享语义组。
9. 对记录进行解析质量分层。

这里的2,019条不是从49,922条中选出的样本，而是49,922条路径去除实例日期和存储位置后形成的2,019种唯一语义组合。全部原始路径仍然保留在逐路径输出中。

### 6.3 关键结果

- 输入路径：49,922条。
- 逐路径Embedding输入：49,922条。
- 唯一静态语义组：2,019个。
- 语义目录相对逐路径记录比例：4.04%。
- `supported_clean`：49,618条。
- `supported_with_unresolved`：88条。
- `fallback_raw`：216条。
- 分离出观测日期：49,533条。
- 分离出观测年份：38,023条。
- 空Embedding文本：0条。
- 路径索引重复：0条。
- 静态文本实例时间泄漏检查：通过。

### 6.4 输出

正式制品：`processed/artifacts/path_semantics/v1/`；质量报告：`processed/reports/path_semantics/05_embedding/`

- `步骤5_Embedding输入生成与全流程总结.md`。
- `embedding_records.csv.gz`：49,922条逐路径输入和旁路字段。
- `semantic_catalog.csv.gz`：2,019条唯一静态语义。
- `embedding_record_samples.jsonl`：分质量层抽取的可读样例。
- `step5_summary.json`：总体统计。

实现脚本：`path_semantics/05_build_embedding_inputs.py`。

## 7. 五步产物之间的关系

```text
步骤1回答：真实路径长什么样，原规则哪些地方不成立？
步骤2回答：每个Token可能是什么类型，证据和置信度是多少？
步骤3回答：主流路径如何按分支和状态解析为字段？
步骤4回答：如何安全覆盖更多高价值分支，同时避免伪造语义？
步骤5回答：如何把解析字段转成模型输入，并建立语义组到具体路径的一对多映射？
```

最终数据关系为：

```text
2,019个semantic_group_id
        ↓ 一对多映射
49,922条目录路径实例
```

静态语义、路径实例、访问行为和资源成本被分别保存，便于后续模型在不混淆不同信息来源的情况下进行训练和检索。
