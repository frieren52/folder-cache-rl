# 主要输出文件、样例解析与后续训练计划

## 1. 文档目的

本文说明五步流程完成后最重要的输出文件、这些文件之间的关系、一个真实路径样例如何被解析，以及这些产物如何进入后续的静态路径向量和历史访问模型训练。

## 2. 最主要的输出文件

### 2.1 最终逐路径记录

文件：`processed/artifacts/path_semantics/v1/embedding_records.csv.gz`

规模：49,922行，每条原始目录路径一行。

主要字段：

| 字段 | 含义 | 后续用途 |
| --- | --- | --- |
| `path_index` | 当前数据集内的稳定行索引 | 与其他统计或向量索引关联 |
| `path` | 原始目录路径 | 追溯、PathEncoder输入、人工检查 |
| `semantic_group_id` | 不含实例日期的静态语义组ID | 将共享语义向量映射回具体路径 |
| `embedding_text` | 推荐的中文语义输入 | 输入BGE生成语义向量 |
| `semantic_text_strict` | 只保留高置信解释字段的文本 | 消融实验和高精度子集训练 |
| `semantic_sequence` | 字段和值的结构化序列 | PathEncoder、特征审计、结构化模型输入 |
| `semantic_sequence_strict` | 高置信结构化序列 | 严格版本对比 |
| `source_context` | 存储根目录、子系统和解析路由 | 路径实例编码或类别特征 |
| `instance_context` | 观测年份、日期和实例编号 | 路径实例编码；不进入共享语义组 |
| `quality_tier` | 当前路径解析质量 | 训练过滤、分层抽样、索引分区 |
| `parser_route` | 使用的路径解析器 | 错误分析和分支评估 |
| `mean_semantic_confidence` | 解释字段平均置信度 | 训练样本权重或过滤条件 |
| `access_count` | 当前聚合数据中的访问次数 | 热度统计或样本权重，不进入静态语义文本 |
| `total_size_bytes` | 当前路径聚合数据大小 | 成本感知预取和最终排序 |
| `observe_year`、`observe_date` | 观测时间 | 路径实例特征；与用户访问时间不同 |

该文件保存了全部路径，没有因为语义去重而丢弃记录。

### 2.2 去重静态语义目录

文件：`processed/artifacts/path_semantics/v1/semantic_catalog.csv.gz`

规模：2,019行，每个唯一静态语义组合一行。

主要字段：

| 字段 | 含义 |
| --- | --- |
| `semantic_group_id` | 语义组主键 |
| `embedding_text` | 推荐的BGE输入文本 |
| `semantic_text_strict` | 高置信文本 |
| `semantic_sequence` | 规范化结构序列 |
| `path_count` | 有多少具体路径共享该语义 |
| `total_access_count` | 该语义组聚合访问次数 |
| `total_size_bytes` | 该语义组聚合数据大小 |
| `quality_tiers_json` | 组内路径质量分布 |
| `parser_routes_json` | 组内路径解析路由分布 |
| `example_paths` | 用于人工检查的原始路径示例 |

`example_paths`中可能包含日期，但它只是审计信息。实际输入BGE的`embedding_text`不包含观测年份和观测日期。

### 2.3 可读样例

抽样文件不再长期保存；需要时从 `processed/artifacts/path_semantics/v1/embedding_records.csv.gz` 确定性抽样。

这是从49,922条逐路径记录中按质量层抽取的样例。每一行是一个独立JSON对象，方便人工检查解析是否合理。它不是2,019条语义目录的完整导出，也不用于正式批量训练。

### 2.4 全量结构化解析结果

文件：`processed/artifacts/path_semantics/v1/parsed_paths.csv.gz`

这是字段最完整的中间结果，除规范字段外还保存：

- 每个字段的原始值、规范值、来源深度、置信度和证据。
- 列表字段的逐项元数据。
- 字段冲突和解析告警。
- 未解释Token。

如果后续需要训练自己的PathEncoder、调整字段置信度或重新生成不同文本模板，应从这个文件开始，而不是从最终文本反向恢复字段。

### 2.5 路由、字段与未知Token统计

目录：`processed/reports/path_semantics/04_parser_expanded/`

- `route_summary.csv`：每种路径语法的数量和解析状态。
- `field_coverage_by_route.csv`：各路由中字段覆盖率。
- `field_value_catalog.csv`：字段值频次和路径示例。
- `unresolved_extra_tokens.csv`：仍待业务确认的Token。
- `field_conflicts.csv`：字段竞争明细。
- `remaining_fallback_routes.csv`：非专用分支分布。

这些文件主要用于规则维护、业务代码表补充和训练数据质量分析。

## 3. 输出文件之间的关系

```text
parsed_paths.csv.gz
    │  全量字段、证据、置信度
    ▼
embedding_records.csv.gz（49,922条具体路径）
    │
    ├── semantic_group_id ──► semantic_catalog.csv.gz（2,019种共享语义）
    │
    ├── source_context ─────► 存储位置/路径实例特征
    │
    ├── instance_context ───► 观测日期/实例编号特征
    │
    ├── access_count ───────► 热度或训练权重
    │
    └── total_size_bytes ───► 预取成本特征
```

2,019不是被选中的路径数量，而是49,922条路径在去除实例日期和存储位置之后形成的唯一语义组合数量。

## 4. 真实样例逐项解析

从`embedding_record_samples.jsonl`中选取以下真实样例：

```text
/FYDATAOUTSHARE/DATAIOT/FY3/FY3F/GNOSO/L1/IEG/2026/20260522
```

原始聚合属性：

```text
访问次数：4525
聚合数据大小：109864266字节
```

### 4.1 路径分层

| 深度 | 原始Token | 解析角色 | 输出值 |
| ---: | --- | --- | --- |
| 0 | `FYDATAOUTSHARE` | 存储根目录 | `FYDATAOUTSHARE` |
| 1 | `DATAIOT` | 子系统 | `DATAIOT` |
| 2 | `FY3` | 数据域 | `FY3` |
| 3 | `FY3F` | 卫星或航天平台 | `FY3F` |
| 4 | `GNOSO` | 载荷或仪器 | 规范化为`GNOS` |
| 5 | `L1` | 数据等级 | `L1` |
| 6 | `IEG` | 产品代码 | `IEG` |
| 7 | `2026` | 观测年份 | `2026` |
| 8 | `20260522` | 观测日期 | `20260522` |

该路径命中专用路由：

```text
outshare_dataiot_fy3
```

解析质量：

```text
quality_tier = supported_clean
route_supported = 1
has_unresolved_tokens = 0
mean_semantic_confidence = 0.952
min_semantic_confidence = 0.78
```

### 4.2 中文语义输入

```text
数据域 FY3；卫星或航天平台 FY3F；载荷或仪器 GNOS；数据等级 L1；产品 IEG
```

这是推荐送入BGE的`embedding_text`。它保留了文件“是什么”的信息，同时去除了重复出现的存储前缀和具体日期。

### 4.3 结构化语义序列

```text
[DOMAIN=FY3][SATELLITE=FY3F][INSTRUMENT=GNOS][LEVEL=L1][PRODUCT=IEG]
```

这是`semantic_sequence`。它与中文文本表达同一组语义，但字段边界更加明确，适合：

- 训练字段级PathEncoder。
- 生成类别Embedding。
- 检查某个字段是否缺失。
- 构造同字段、不同值的难负样本。

### 4.4 存储位置上下文

```text
[ARCHIVE_ROOT=FYDATAOUTSHARE]
[SUBSYSTEM=DATAIOT]
[ROUTE=outshare_dataiot_fy3]
```

对应`source_context`。它不参与2,019个共享语义组划分，但可以进入路径实例编码器或作为检索过滤条件。

### 4.5 路径实例上下文

```text
[OBSERVE_YEAR=2026]
[OBSERVE_DATE=20260522]
```

对应`instance_context`。它用于区分同一产品在不同观测日期的路径。观测时间是文件身份的一部分，但不是访问行为时间，因此不应与用户访问日志中的时间戳混为一谈。

### 4.6 语义组和路径实例的关系

假设还存在：

```text
/FYDATAOUTSHARE/DATAIOT/FY3/FY3F/GNOSO/L1/IEG/2026/20260523
```

两条路径可以共享同一个：

```text
semantic_group_id
```

但它们的`instance_context`不同。由此得到：

```text
共享语义向量：相同或非常接近
路径实例向量：能够区分20260522和20260523
最终静态路径向量：相近但不完全相同
```

## 5. 如何用于后续训练

### 5.1 第一阶段：建立无需微调的静态语义基线

输入：`semantic_catalog.csv.gz`中的`embedding_text`。

处理：使用选定的BGE模型批量编码，并进行L2归一化。

预期输出：

```text
semantic_vectors.npy
semantic_vector_index.csv
```

如果选择1024维模型，则向量矩阵形状约为：

```text
[2019, 1024]
```

`semantic_vector_index.csv`保存：

```text
vector_row, semantic_group_id
```

通过`semantic_group_id`把语义向量映射回49,922条路径。该阶段可以验证结构化语义文本是否比直接Embedding原始路径更适合相似文件检索。

建议至少比较三种输入：

1. 原始路径字符串。
2. `semantic_text_strict`。
3. 推荐的`embedding_text`。

### 5.2 第二阶段：建立有区分度的路径实例向量

仅有共享语义向量会让不同日期实例得到相同向量，因此需要路径实例编码器。

路径实例编码器的输入建议包括：

```text
semantic_sequence
+ source_context
+ instance_context
+ 原始路径中仍需保留的Token和层级位置
```

实现可以分两步：

#### 基线方案

将上述字段构造成带标签文本，再使用同一个BGE编码。该方案实现简单，可以快速验证不同日期和存储位置能否产生可观测差异。

#### 正式方案

训练小型PathEncoder：

```text
字段类别Embedding
+ Token/Subword Embedding
+ 路径层级位置Embedding
+ 日期数值/Fourier编码
→ Transformer
→ 路径实例向量
```

对于观测日期，除原始`YYYYMMDD`外，建议拆出：

- 年、月、日。
- 一年中的第几天。
- `sin(day_of_year)`和`cos(day_of_year)`。
- 可选的绝对日序号。

这样相邻日期能够保持接近，同时仍然具有区分度。

### 5.3 第三阶段：构造最终静态路径向量

设：

- `s_i`为BGE生成的共享语义向量。
- `p_i`为PathEncoder生成的路径实例向量。

可以不使用MLP，直接加权拼接：

```text
v_static_i = Normalize([√α · s_i ; √(1-α) · p_i])
```

初始可设：

```text
α = 0.8
```

此时余弦相似度等价于：

```text
0.8 × 语义相似度 + 0.2 × 路径实例相似度
```

效果目标是：

- 同卫星、同仪器、同产品的路径保持接近。
- 日期、分辨率、等级、来源或实例编号不同的路径不完全重合。

预期输出：

```text
path_instance_vectors.npy
static_path_vectors.npy
path_vector_index.csv
```

### 5.4 第四阶段：训练历史访问行为模型

当前目录聚合数据只有`access_count`和聚合大小，没有逐次访问时间序列，因此不能单独用它构造“历史访问 → 下一文件”的训练样本。

还需要事件级访问日志，至少包含：

```text
访问时间戳
文件或目录ID
用户、节点或会话ID（如果存在）
读取字节数或读取完成状态（如果存在）
```

按用户、节点或会话排序后构造：

```text
输入：最近N次访问的路径序列
正样本：下一次真实访问的路径
负样本：未被访问的其他路径
```

历史模型可以使用Transformer、GRU或TCN，并额外输入：

- 访问时间间隔。
- 小时、星期、日期周期编码。
- 文件静态向量。
- 过去窗口内的访问次数和最近一次访问距离。

模型输出动态查询向量`q_dynamic`或每个文件的长期行为向量`v_dynamic_i`。

### 5.5 第五阶段：对比学习和难负样本

训练目标建议使用InfoNCE或采样Softmax：

```text
历史查询向量与下一真实文件向量相似
历史查询向量与负样本文件向量不相似
```

必须加入难负样本，否则模型容易只学到卫星大类：

1. 同卫星、同仪器、同产品，但观测日期不同。
2. 同日期、同卫星，但产品不同。
3. 同产品，但等级或分辨率不同。
4. 语义非常接近但下一时刻没有访问的路径。
5. 高频文件作为流行度负样本，防止模型只推荐热门项。

`semantic_sequence`能够直接用于高效筛选这些难负样本。

### 5.6 第六阶段：双向量匹配

按照静态语义与历史行为分离的设计，每条路径维护：

```text
v_static_i：语义 + 路径实例
v_dynamic_i：长期访问行为
```

查询侧输出：

```text
q_static
q_dynamic
```

最终得分可以直接加权，不需要MLP：

```text
score(i)
= λ × cosine(q_static, v_static_i)
+ (1-λ) × cosine(q_dynamic, v_dynamic_i)
```

也可以分别在两个向量索引中召回候选，再对候选集合进行加权排序。

`total_size_bytes`不进入余弦向量，但可以用于成本调整：

```text
prefetch_score
= relevance_score
- β × normalized_size
```

具体是否惩罚大文件应由字节命中收益和网络带宽约束共同决定，不能默认文件越大越差。

### 5.7 数据划分与评估

访问数据必须按时间划分，不能随机打乱，否则未来访问可能泄漏到训练集。

七天数据可以先采用：

```text
第1—5天：训练
第6天：验证
第7天：测试
```

需要同时报告：

- Recall@K：下一真实文件是否进入预取候选。
- HitRate@K。
- MRR或NDCG：真实文件的排序位置。
- 字节命中率：命中的有效读取字节占比。
- 无效预取率：预取后未被访问的数据比例。
- 带宽放大率和缓存占用。
- 按卫星、仪器、产品、日期跨度和质量层分组的指标。

## 6. 质量层如何参与训练

### `supported_clean`

49,618条。用于第一版静态编码、PathEncoder训练和主要评估集。

### `supported_with_unresolved`

88条。主体结构可信，可以保留未知Token并降低样本权重；同时作为业务代码表补充的优先对象。

### `fallback_raw`

216条。主要是软件库、日志、质控和其他非卫星目录。建议：

- 单独建立类别或索引分区。
- 不把它们作为卫星产品难负样本。
- 使用原始路径Token编码，避免强行填充卫星字段。

## 7. 推荐的最小可运行训练顺序

1. 对2,019条`embedding_text`生成BGE语义向量。
2. 通过`semantic_group_id`映射回49,922条目录路径。
3. 使用`source_context`、`instance_context`和完整路径建立路径实例向量基线。
4. 加权拼接语义向量和路径实例向量，得到每条路径的静态向量。
5. 准备事件级访问日志，按时间构造下一路径预测样本。
6. 训练历史访问模型，并使用同语义不同实例作为难负样本。
7. 分别计算静态、动态得分，再加权排序。
8. 在第7天测试Recall@K、字节命中率和无效预取率。

## 8. 当前限制与进入训练前的必要确认

1. 当前对象是目录路径，不是目录内具体文件。若要一文件一向量，需要补充完整文件名。
2. 2,019条语义可以生成共享语义向量，但不能单独作为最终有区分度的路径向量。
3. `access_count`是聚合统计，不能替代事件级历史访问序列。
4. BGE模型尚未下载或执行，当前产物是经过验证的模型输入，不是最终浮点向量。
5. `SPAC`、`MOS`、`RNE`等业务缩写仍需正式代码表确认。
6. 正式训练前需要确定查询对象：用户、计算节点、缓存节点还是全局访问流。该选择决定历史序列如何划分。
