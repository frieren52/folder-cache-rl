# 文件夹粒度的强化学习缓存预测算法

本项目面向文件夹粒度的缓存决策：在固定缓存容量和 LRU 机制约束下，结合目录静态语义、近期访问历史、监督预训练与强化学习，提高缓存命中效果，并通过基线、归因和消融实验验证收益。

## 项目结构

```text
01_业务与方案/             业务约束、总体架构和各模块设计
02_全局数据/               数据处理流水线与分析代码
03_静态语义向量生成/       目录路径静态语义编码
04_动态历史向量生成/       近期访问历史编码与需求预测
05_监督微调/               Actor 监督预训练与自然候选召回评价
06_强化学习/               强化学习训练模块
07_评估与消融实验/         综合评价和消融实验
docker/                    容器入口脚本
```

建议先阅读 [`01_业务与方案/业务约束.md`](01_业务与方案/业务约束.md)，再阅读 [`01_业务与方案/设计方案/00_总体架构/总体方案.md`](01_业务与方案/设计方案/00_总体架构/总体方案.md)。

## 开发环境

项目采用 Docker-first 工作流，目标环境为 `linux/amd64`、Ubuntu 22.04 和 Python 3.10。所有依赖、测试、分析和训练命令均通过根目录的 `dev.ps1` 进入容器执行。

```powershell
# 构建开发镜像
pwsh -NoProfile -File ./dev.ps1 build

# 验证容器环境
pwsh -NoProfile -File ./dev.ps1 smoke

# 运行 LRU 基线和 MISS 归因分析
pwsh -NoProfile -File ./dev.ps1 baseline
pwsh -NoProfile -File ./dev.ps1 miss-attribution
```

更多说明见 [`DOCKER.md`](DOCKER.md) 以及各模块目录下的 `README.md`。

## 数据与模型

仓库只保存代码、配置和设计文档。以下内容不会提交到 Git：

- `02_全局数据/raw/` 中的原始访问日志；
- 从原始数据生成的分析结果和中间制品；
- 下载的基础模型、训练数据、检查点和评估输出；
- 本地环境变量、缓存、日志和离线发布包。

运行时应把原始数据只读挂载到容器，并为每次实验使用独立输出目录或运行编号。必要的数据格式和生成步骤记录在各模块说明中。
